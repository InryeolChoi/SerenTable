## 실제 공개 API 검증

[검증 스크립트](../../scripts/verify_deployed_application.py)를 Railway API 컨테이너 안의 Python 표준 라이브러리로 실행했다. 요청은 내부 ASGI나 DB 직접 접근이 아닌 공개 HTTPS를 통과한다. 두 합성 계정 비밀번호는 컨테이너 환경에서만 읽고 로컬 복사·출력·저장소 기록을 하지 않았다.

통과 항목:

- 운영자·참가자 실제 로그인, 민감 응답 no-store, 참가자의 운영 API 접근 403.
- 합성 프로필·동의 완료, 운영자 회차 생성 → 참가자 모집 회차 조회.
- 신청 생성 → 동일 요청 재전송의 같은 신청 반환.
- 1회권 모의 결제 FAILED → 새 요청으로 PAID(9,900원·mock=true).
- 동일 결제 재전송의 같은 결제 반환, 이용권 추가 발급 없음.
- 참가자 신청의 매칭 적격 상태와 운영자 신청 목록 조회.
- 검증 신청 취소(CANCELED), 이용권은 하나만 존재, 두 계정 로그아웃.

23개 고정 PASS 출력과 종료 코드0을 확인했다. 첫 시도는 런타임에 테스트용 httpx가 없어 요청 실행 전에 실패했고, 운영 패키지 추가 없이 표준 라이브러리로 바꿔 통과했다.

검증용 회차1개·취소된 합성 신청1개·실패/성공 모의 결제 각1건·보유 1회권1개가 남는다. 실제 청구는 없고, 취소를 환불로 바꾸지 않았다. 완성되지 않았던 합성 계정의 프로필·동의만 채웠다. 원본 자료·실제 개인정보를 적재한 검증이 아니다.
