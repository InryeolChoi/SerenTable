# ADR-0016: 심사 기간 데이터 보관·폐기와 기각 신고의 분리 해제 (U16)

- 상태: 사용자 정책 승인(2026-10-19), 구현·격리 검증 완료. **2026-10-19 main 병합·운영 배포됨**(PR #54 → `b633118`). 실제 데이터 폐기는 심사 결과 안내 이후이므로 아직 수행하지 않았다.
- 범위: 모임 안내·피드백·재방문(식당·채팅·알림, 참석·피드백·다음 추천)과 운영자 예외·안전 종합 관리의 U16 조건
- 근거: 사용자 2026-10-19 답변, ADR-0008(합성 계정·비공개 프로필), ADR-0014(신고 즉시 분리), 구현 명세 §7(실제 PG 제외)

## 결정

**보관·폐기.** 운영 데이터는 합성 계정만 쓰며 실제 개인정보·실제 결제가 없다(실제 PG 연결은 하지 않기로 2026-10-19 재확인). 그래서 항목별 보관 기간과 자동 삭제를 만들지 않는다. 심사 결과 안내 때까지 동의·신청·모의 결제·매칭·채팅·알림·체크인·피드백·신고·제재·운영자 감사 기록을 모두 보관한다. 감사 기록은 덧붙이기만 하며 화면·API로 수정·삭제하지 않는다. 결과 안내 뒤 운영 PostgreSQL과 그 백업(로컬 `.local-backups/` 포함)을 통째로 폐기한다. 폐기는 사용자가 실행하며 실행 시 운영 데이터 변경 승인 절차를 따른다. 실제 서비스 전환 시의 항목별 보관 기간·자동 삭제·동의 철회 후 처리는 MVP 범위 밖이며 출시 전에 다시 정한다.

**기각 신고의 분리 해제 (ADR-0014 U09 개정).** 신고 접수 즉시 쌍을 분리하는 규칙은 그대로다. 기존의 "기각돼도 분리 유지"를 바꿔, 운영자가 **기각(DISMISSED)한 신고에 한해** 사유를 입력해 그 신고의 분리(`participant_exclusion.source='report'`)를 해제할 수 있다.

- 같은 두 사람 사이에 처리 중(OPEN)이거나 확인(CONFIRMED)된 신고가 하나라도 있으면 해제하지 않는다(`409 pair_has_active_report`).
- 차단(`block`)·다시 만나고 싶지 않음(`avoid`) 등 다른 이유의 분리는 남는다. 해제 뒤 새 신고가 들어오면 다시 즉시 분리된다.
- 해제는 매칭 잠금 아래 한 트랜잭션에서 하고 `report.release_separation` 감사 기록(사유, 분리 전후 상태만)을 남긴다. 신고 상세 문구는 감사 기록에 넣지 않는다. 같은 요청을 다시 보내면 같은 결과를 돌려주고 감사 기록을 더 만들지 않는다.
- 신고와 해제 사실은 피신고자에게 계속 공개하지 않는다.

## 결과

- API: `POST /api/admin/reports/{id}/release-separation` `{reason}`(운영자·CSRF). 신고 목록 응답에 `separation_active`를 더한다.
- 운영자 화면: 기각된 신고에 사유 입력과 「매칭 분리 해제」 버튼, 해제 후 "매칭 분리 해제됨" 표시.
- 스키마·migration 변경 없음. 이미 확정된 모임은 바꾸지 않는다.
- U16 확정으로 Work「식당·채팅·알림」「참석·피드백·다음 추천」 인수 기준의 U16 항목이 채워진다. 운영자 역할 분리·기존 운영 조치 전반의 사유 필수화(ADR-0015 범위 밖 항목)와 U19는 여전히 미정이다.
