# PRD 정렬 매칭 점수·최소 점수·전체 배정 목적함수

2026-10-17 사용자 조건부 승인. ADR-0010의 **결정 2(인원 최대 → 모든 쌍 Jaccard 합 → 신청 순서)를 대체**한다. ADR-0010 결정 1(독립 합성 참가자 100명)과 후속 B안은 유지한다. 근거 원문 대조는 [PRD·킥오프 결정 정리](../design/prd-kickoff-decisions.md)를 따른다.

## 배경

PRD §7.0은 "조건별 점수를 합산해 가장 좋은 조합 선택", 자동 확정 기준 "필수 조건 전체 충족 + 운영자가 설정한 최소 매칭 점수 이상", 최소 점수 미달 시 재배치 또는 대체 일정 안내를 정한다. MAT-04는 연령대 → 성비 → MBTI 궁합 → 관심사 → 만나고 싶은 사람 순서를, MAT-06은 새로운 사람 우선을 요구한다. 가중치·점수표·최소 점수 값·목적함수·탐색 방법은 PRD·킥오프에 없다. 공식 FAQ Q7·Q8·Q10과 "PRD에 없는 운영 정책은 개발팀이 결정"에 따라 아래를 **자체 설계안**으로 정한다. 실제 만족도 데이터로 추정한 값이 아니다.

기존 `age-ordered-dp-v2`는 운영에서 정상 동작했다(2026-10-17 홍대 합성100명, 확정100). 이 결정은 엔진 재작성이 아니라 그 결과를 시작점으로 하는 개선이며, worker·스케줄·확정 트랜잭션·이용권 처리는 바꾸지 않는다.

## 1. 계층

1. **필수조건 검증**: 테이블·배정이 아래 H1~H7을 만족하는지 판정한다. 점수와 독립이다.
2. **테이블 점수**: 한 테이블의 구성만으로 0~100 점수를 계산한다. 배정 전체와 독립이다.
3. **전체 배정**: 회차의 후보 전체를 4절 목적함수로 나눈다.

각 계층은 공개 함수 경계로 따로 시험한다.

## 2. 필수조건 (완화 금지)

- H1 대상: 회차 마감 기준 결제 완료·SUBMITTED·살아 있는 후보 신청(기존 `eligibility`).
- H2 날짜·지역: 같은 회차 안에서만 테이블을 만든다.
- H3 인원: 테이블당 4~6명.
- H4 연령: 테이블 구성원 모두 출생연도가 있고 `최대 출생연도 − 최소 출생연도 ≤ 8`. 출생연도가 없으면 배정하지 않는다(`unknown_age`). 앱에는 출생연도만 있으므로 만 나이로 계산하지 않는다.
- H5 제외 관계: 같은 테이블의 어떤 두 사용자도 제외 관계가 아니다. 제외 관계는 사용자 쌍 단위·대칭이며 PRD MAT-05의 차단·**확정된** 신고·"다시 만나고 싶지 않음"에서 온다. 접수만 된 신고는 운영자 확인 대상이며 이 결정으로 자동 제외하지 않는다(U09는 신고 확정 절차가 생길 때 다시 본다). 이번 범위에서는 저장 구조만 만들고 채우는 기능은 A4-W2에서 구현한다.
- H6 중복: 한 **사용자**는 한 실행에서 한 테이블에만 앉고, **시간이 겹치는** 다른 회차에서 이미 CONFIRMED인 사용자는 대상이 아니다(PRD §7.4 "동시에 두 테이블"). 날짜가 다른 회차는 멤버십의 기간 내 참여이므로 막지 않는다. 이 신청은 `NO_MATCH`(`overlapping_confirmation`)로 끝나며 대안을 제시하지 않는다.
- H7 정원: 앉은 인원의 합 ≤ 회차 정원.

## 3. 테이블 점수 `S(T)`

테이블 T의 구성원 수를 n, 서로 다른 두 사람의 쌍 수를 `P = n(n−1)/2`라 한다. 각 항목 `S_k(T)`는 0~100이며 항목마다 실제 분포 폭이 다를 수 있다. 분포 폭을 인위적으로 늘리지 않는다.

| k | 항목 | 정의 | 계산 불가 |
|---|---|---|---|
| age | 연령대 | `100 × (1 − (최대 출생연도 − 최소 출생연도) / 8)` | 없음(H4가 보장) |
| gender | 성비 | 앞뒤 공백을 지운 성별이 정확히 `남성` 또는 `여성`인 사람만 센다. 그 수를 m, f, `k = m + f`라 할 때 `100 × min(m, f) / ⌊k/2⌋` | `k < 2` |
| mbti | MBTI | 쌍마다 두 사람이 고른 유효 MBTI(16개 표준 유형, 대문자) 조합 중 서로 다른 차원 수의 최솟값 d를 쓰고 `c = 100 − 5·d`(M1). 유효 유형이 없는 사람이 포함된 쌍은 뺀다. 남은 쌍의 평균 | 유효 쌍 0개 |
| interest | 관심사 | 쌍마다 `100 × |A∩B| / |A∪B|`(공통 관심사 비율), 두 사람 모두 비었으면 그 쌍을 뺀다. 남은 쌍의 평균 | 유효 쌍 0개 |
| trait | 희망 상대 성향 | 아래 대응표로 순서쌍 (i, j), i≠j마다 i의 희망 성향 집합 D(비어 있으면 i 제외)에 대해 `s(i,j) = 평균_{d∈D} 충족_d(i,j)`. 전체 순서쌍 평균 × 100 | 유효 순서쌍 0개 |
| new | 새로운 사람 비율 | `100 × (1 − 이전에 만난 쌍 수 / P)`. 이전에 만난 쌍은 두 사용자가 과거 실행에서 같은 테이블에 CONFIRMED로 배정된 적이 있는 쌍 | 없음 |

희망 성향 대응표(`충족_d(i,j)`는 0 또는 1, 단 similar/different는 0~1):

| 희망 성향 d | 충족 기준 |
|---|---|
| deep_conversation | j의 본인 성향에 deep_conversation |
| comfortable_humor | j의 본인 성향에 light_humor |
| calm_stable | j의 본인 성향에 calm 또는 listener |
| passionate | j의 본인 성향에 energetic 또는 conversation_leader |
| similar | i와 j 본인 성향의 Jaccard(둘 다 비면 0) |
| different | 1 − i와 j 본인 성향의 Jaccard(둘 다 비면 0) |

**가중합:** `S(T) = Σ_k w_k · S_k(T) / Σ_{계산 가능한 k} w_k`. 계산 불가 항목은 빼고 나머지 가중치를 비율대로 다시 맞춘다. 모든 계산은 정확한 유리수로 하며 기록 시 소수 둘째 자리로 반올림한다.

**초기 가중치(실험용 가설, 정책 `prd-weighted-v1`):** age 0.25, gender 0.20, mbti 0.15, interest 0.15, trait 0.10, new 0.15. 합은 1이다.

- **순서와 크기의 구분:** MAT-04 순서는 가중치를 앞 항목 ≥ 뒤 항목으로 두는 방식으로 반영한다. 실제 영향력은 `가중치 × 항목 점수의 실제 분포 폭`이므로 가중치 순서가 결과의 사전식 우선순위를 보장하지 않는다. 특히 M1 MBTI는 80~100 사이라 영향력이 작다. 이것이 의도한 결과인지는 실험(6절)으로 평가하며 통계 근거 없이 폭을 키우지 않는다.
- MBTI 유사도·성향 대응표는 검증된 궁합표가 아니라 설명 가능한 보수적 휴리스틱이다(FAQ Q8). McCrae & Costa(1989)·Dyrenforth 외(2010)는 16유형 궁합 점수표를 검증한 연구가 아니며 이 식의 근거로 인용하지 않는다.

## 4. 전체 배정 목적함수

후보 배정들을 다음 순서로 사전식 비교한다.

1. H1~H7을 모두 만족한다.
2. 모든 테이블이 `S(T) ≥ m`(최소 매칭 점수)이다. 미달 테이블은 만들지 않는다.
3. 앉은 인원이 많다.
4. `Σ_T n_T · S(T)`(참가자 수로 가중한 품질 합)가 크다.
5. 가장 낮은 테이블 점수가 크다.
6. 먼저 신청한 사람을 앉힌 쪽(기존 제출 우선 비트마스크 비교).

**최소 매칭 점수 m:** 정책 값이다. 2026-10-18 사용자가 40·50·60·70·80 민감도 분석([실험 기록](../design/matching-experiments-2026-10-17.md)) 후 **운영값 60**을 승인했다(이전 개발용 임시값 50). 가상데이터 4개 묶음에서 인원 손실 최대 2명, 최저 테이블 점수 61 이상이다. `MATCHING_MIN_SCORE` 환경 변수로 덮어쓸 수 있으며 회차별 값과 운영자 설정 화면(MAT-15, P1)은 후속이다.

## 5. 엔진의 보장과 한계

엔진은 기존 DP로 확정 인원이 최대인 초기 배정을 만든 뒤 제외·최소 점수 위반 테이블을 수리하거나 해체하고, 해체된 사람의 재착석과 인원을 유지하는 교환으로 품질을 개선한다. 같은 입력이면 같은 결과이며 100명 회차 5초 상한을 둔다.

- 보장: H1~H7 위반 0, 최소 점수 미달 테이블 0, 확정 인원 ≤ 기존 DP 인원(제약이 더해졌으므로).
- 보장하지 않음: 4절 목적함수의 전역 최적. 국소 최적에 머물 수 있다. 10명 이하 완전탐색 정답과 비교해 차이를 측정·보고한다.
- 최소 점수 0·제외 관계 없음이면 확정 인원이 기존 DP와 같아야 한다. 이는 회귀 기준일 뿐 일반 최적성의 증거가 아니다.

## 6. 검증 구분

- Correctness: PRD 요구별 실제 PostgreSQL·worker 시험, `ALTERNATIVE_OFFERED` 전환, 사용자 중복 금지.
- Feasibility: 엔진 코드를 재사용하지 않고 이 ADR만으로 작성한 독립 검증기가 모든 결과를 재검사.
- Optimization Quality: 10명 이하 완전탐색 정답 대비 목적함수 차이, 기존 DP 대비 인원, 그리디 반례.
- Robustness: 입력 순서·시드 변화 재현성, 누락·비표준 MBTI, 100명 시간.
- Predictive Validity: **검증할 수 없다.** 만족도 정답이 없어 어떤 가중치·정책이 실제 만족을 높이는지 주장하지 않는다. 실험은 공통 지표(인원, 성공률, 테이블 수, 미매칭, 평균·최소 점수, 위반, 시간, 가중치 변경 시 테이블 구성 변화)만 비교한다.

## 7. 실패 상태

배정되지 못한 신청은 PRD대로 `ALTERNATIVE_OFFERED`(대체 일정·보관·환불 선택 대기)로 기록한다. 기존 DP도 앉힐 수 없던 사람은 기존 사유(`age_gap` 등)를, 기존 DP는 앉힐 수 있었지만 탐색이 제외 관계·최소 점수를 함께 만족하는 테이블을 찾지 못한 사람은 `no_qualifying_table`을 받는다. 국소 탐색이므로 "불가능"을 단정하는 사유를 쓰지 않는다. `NO_MATCH`는 H6의 시간 겹침 신청에만 쓴다. 기존 `NO_MATCH` 행은 변환하지 않으며 대안 조회는 두 값을 모두 허용한다. 현재 `/alternatives`는 **읽기 전용**이고 실제 이동·보관·환불 선택은 미구현이다. 이는 PRD P0(STA-05·STA-06·PAY-03)이며 Work #6에서 추적한다.

## 적용 범위

새 정책은 배포 이후 매칭 시각이 오는 회차에만 적용한다. 이미 실행된 운영 결과는 재실행·변경하지 않는다. 운영 마이그레이션·배포는 별도 승인 후 수행한다.
