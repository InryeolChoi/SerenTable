# ADR-0019: PRD §14 참가자 알림과 PAY-02 환불·노쇼 문구

- 상태: 사용자 승인(2026-10-21)
- 위치: 운영자 예외·최종 검증·제출 → 통합 검증·제출(#10). PRD 정합성 감사(`docs/design/prd-conformance-audit-2026-10-21.md`) 1.1·1.7·1.8의 후속이다. 신규 Work/Task는 추가하지 않는다.

## 결정

1. **§14 알림:** 테이블 밖 상태 변화에도 앱 알림(+구독 기기 푸시)을 만든다. 상태 변경과 같은 트랜잭션에서 만들고, 대상별 event key(`application:<id>:submitted`, `payment:<id>:paid`, `match-failed:<run>:<application>`, `resolution:<id>:moved|held`, `refund:<id>:completed|failed`)로 멱등성을 지킨다.
   - 신청 완료와 결제 대기: 한 알림으로 보낸다. 신청 직후에는 항상 결제 대기 상태이므로 결제 기한(가장 이른 신청 마감)을 함께 안내한다.
   - 결제 완료, 매칭 실패(사유와 선택지), 일정 이동 완료, 환불 완료(실패 시 운영자 재처리 안내), 이용권 보관
   - 잠금화면 푸시는 기존대로 일반 문구만 보여 주고, 상세 내용은 앱 안에만 둔다(`sw.js`).
   - 보내지 않는 것: "자동 재배치 중"은 이 엔진에 별도 재배치 단계가 없어 상태 자체가 없다(감사 1.5). "다음 모집 시작"은 참가 이력의 다음 일정 추천(RET-02) 화면으로 대신한다.
2. **PAY-02 문구:** PRD 문장을 따른다. FAQ Q1이 "진행 2일 전"의 현행 시점을 화요일 24:00로 답했으므로 "모임 진행 2일 전(현행 기준 화요일 24:00) 이후에는 환불할 수 없습니다"로 표시한다. 당일 취소·노쇼는 FAQ Q2·Q3이 운영 정책을 참가자에게 맡겼으므로, 이미 구현·확정된 동작을 그대로 적는다.
   - 확정 후 앱 내 취소 없음(ADR-0018 U13)
   - 종료 시각까지 체크인하지 않으면 노쇼 후보, 운영자 확인 후 확정 노쇼 또는 사유 인정(ADR-0014 U15)
   - 확정 노쇼는 경고·참가 제한 대상(SAF-02 제재), 사용한 이용권은 돌려받지 않음
   - 결제 전·신청 화면과 하루 전 리마인드 본문에 같은 규정을 적는다.
3. **대체 일정 순서(STA-04, §7.4):** 매칭 실패 후 보여 주는 대체 일정을 PRD 순서로 정렬하고 구분 표시를 붙인다. 신청한 날짜·지역 → 신청한 날짜·다른 지역 → 다른 날짜·신청한 지역 → 다른 날짜·지역 순이고, 같은 묶음 안에서는 이른 회차가 먼저다. 목록에서 빼지 않는다. 어디로 옮길지는 참가자가 고른다(§7.3).

## 바꾸지 않는 것

일반 취소 환불 처리, 노쇼 횟수별 자동 제한, 매칭 엔진의 회차 처리 순서(ADR-0012 U07)는 바꾸지 않는다. 운영 migration은 없다.
