# ADR-0015: 대안 미응답 표시와 모의 환불 실패 복구

- 상태: 사용자 정책 승인, 구현·격리 검증 완료 (2026-10-19). **2026-10-19~20 main 병합·운영 배포됨**(`b633118`). 모의 환불 실패 경로는 운영 정상 흐름에 넣지 않아 로컬 격리 근거만 유지한다.
- 범위: 운영자 예외·최종 검증·제출 → 운영자 예외·안전 종합 관리 → 기능별 예외·조치 연결
- 근거: 사용자 2026-10-19 답변, ADR-0012, 운영자 콘솔 계약

## 결정

대안 미응답은 실패한 원래 회차의 시작 시각이 지난 미해결 신청을 운영자에게 표시하는 기준이다. 참가자의 대안 선택·이용권 보관·모의 환불 권한을 자동 종료하는 기한이 아니다. 임시 시작 시각 기준을 유지하되 그 의미와 승인 여부를 명확히 한다. 별도의 응답 만료·자동 환불·동의 없는 일정 이동은 도입하지 않는다.

모의 환불의 실패 기록과 운영자 멱등 재시도를 구현한다. 실제 PG 취소·부분 환불·멤버십 금액 환불은 추가하지 않는다. 공개 참가자 화면에 임의 실패 기능을 만들지 않으며 실패는 격리 테스트의 저장 장애 주입으로 재현한다.

기존 정상 환불 응답과 완료 이벤트를 유지한다. 환불 처리에 실패하면 결제와 이용권을 환불 완료로 바꾸지 않고, 환불 요청에 예약한 권리를 보존한다. 실패를 기록할 수 있는 범위의 장애와 DB 전체 장애를 구분한다. DB 자체에 기록할 수 없거나 최종 커밋이 실패한 경우에는 요청 전체를 롤백하고 재시도 가능한 오류를 반환한다. 성공을 기록하지 않은 요청을 성공으로 보고하지 않는다.

실패 요청의 참가자 선택은 보존하며 운영자 재시도와 감사 기록은 같은 트랜잭션으로 처리한다. 중복 요청·동시 재시도가 권리 중복 사용이나 중복 환불을 만들지 않도록 기존 공용 매칭 잠금을 재사용한다.

## 대안과 영향

별도 응답 만료 시간을 두면 권리 소멸 정책이 추가되고, 환불 실패 시 전체 요청만 버리면 운영자가 실패를 추적할 수 없다. 현재 MVP에서는 표시와 권리 만료를 분리하고, 저장 가능한 실패에만 별도 처리 이력을 남기는 방식을 채택한다. 실제 외부 결제 도입 시에는 공급자 멱등키·확정 응답 유실·정산 대사를 별도로 설계해야 한다.

감사 보관 기간(U16), 운영자 세부 역할 분리, 기존 운영 조치 전반의 사유 필수화는 이번 승인에 포함되지 않는다. 운영 마이그레이션·배포·기존 데이터 변경·main 병합은 여전히 별도 승인 대상이다.
