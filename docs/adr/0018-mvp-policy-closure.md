# ADR-0018: 남은 MVP 정책을 현재 동작으로 확정

- 상태: 사용자 승인(2026-10-20). 코드 변경 없음.
- 위치: Work #5(U19)·#6(U13)·#9(운영자 역할·조치 사유). 신규 Work/Task는 추가하지 않는다.

제출 마감(2026-10-21)을 앞두고 사용자가 "가장 빠르게 할 수 있는 대안"을 승인했다. 세 항목 모두 이미 구현·검증된 현재 동작을 MVP 정책으로 확정하고, 확장은 실제 서비스 전환 때 다시 정한다.

## U13 확정 후 취소

- 참가자는 신청 마감 전 `SUBMITTED` 신청만 취소할 수 있다(`POST /api/me/applications/{id}/cancel`). 테이블 확정 뒤에는 앱 안에서 취소할 수 없다.
- 확정 후 불참은 기존 노쇼 경로로 처리한다. 종료까지 체크인하지 않으면 노쇼 후보가 되고, 운영자가 사유 인정(면제) 또는 노쇼 확정을 판단한다(ADR-0014).
- PRD §15의 확정 후 자동 충원·재배치(STA-07·MAT-14, P1)는 구현하지 않는다.

## U19 성능·초과 입력

- 수용 기준은 실행당 100명에서 필수조건 위반·중복 배치·참가자 누락이 0건이고, 매칭 1회가 10초 이내인 것이다. 근거는 독립 worker의 100명 확정 시험, 합성 100명 시나리오, 종합 감사 측정(최대 약 2.744초, 탐색 상한 8초)이다.
- 회차 정원은 4~100명이다. 신청 단계에서는 정원 초과를 막지 않는다. 매칭이 정원까지 배정하고, 남은 신청은 `capacity` 미배정 사유로 기존 대안 선택(이동·보관·환불, ADR-0012)을 탄다.
- 수백 명 독립 사용자, 장시간·운영 Railway 부하, 100명을 넘는 단일 실행은 미검증으로 명시한다.

## 운영자 역할·조치 사유

- 운영자 역할은 `operator` 하나만 둔다. 세부 역할 분리는 하지 않는다.
- 자유 서술 사유는 기각된 신고의 분리 해제(ADR-0016)에서만 필수다. 다른 운영 조치는 감사 기록(주체·시각·대상·조치 종류·결과)과 조치 종류 자체(노쇼 확정/사유 인정, 환불 재시도 등)로 갈음한다.
- 역할 분리와 조치 전반의 사유 필수화는 실제 서비스 전환 때 결정한다.
