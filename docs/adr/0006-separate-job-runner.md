# API와 예약 작업 실행기를 분리한다

Railway 한 프로젝트에서 같은 Python 코드베이스를 API용과 작업용으로 나눠 실행한다. 예약 매칭·알림·재시도 작업의 상태는 PostgreSQL에 보관하고 중단 이후 복구와 중복 실행 방지를 검증한다. 구체 라이브러리와 잠금·재시도 정책은 후속 결정이며 Redis/Celery를 필수로 추가하지 않는다.

API 안에서 실행하면 배포 서비스 수는 작지만 API 재배포·장애와 작업 실행이 묶인다. Cron의 간격·실행 지연 대신 별도 실행기를 두어 작업 중단을 독립적으로 재현·검증하는 경험을 확보한다. 추가 메모리·사용량 비용과 배포 관리 부담은 감수한다. 근거: [인터뷰 Q11 재제시](../design/mvp-interview.md), 사용자 답변 “A”.
