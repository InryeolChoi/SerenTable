# ADR-0013: 확정 후 식당 배정과 영속 안내

- 상태: U10·U12 사용자 승인, 구현·격리 검증 진행 / 운영 미반영 (2026-10-17)
- 범위: 모임 안내·피드백·재방문 → Work #7 식당·채팅·알림
- 상세 계약: [gathering-contract.md](../design/gathering-contract.md)

## 결정

확정 매칭은 변경하지 않고 별도 Worker 단계가 식당·단체방·안내를 준비한다. 하나의 가상 재고는 해당 회차의 예약 가능한 테이블 하나이며 중복 배정하지 않는다. 전원 가격대와 정원 조건을 지키고, 음식 제한·알레르기는 전원 명시적 없음 또는 운영자의 해당 테이블·현재 조건 확인을 요구한다. 미확인은 식당 부족 예외이며 AI로 안전 여부를 추정하지 않는다. 실제 예약 API는 호출하지 않는다.

단체방과 앱 내 알림을 PostgreSQL에 저장한다. 확정 멤버만 방을 조회·작성하며 2초 HTTP 폴링과 메시지 커서로 재접속한다. 이벤트 키로 반복 게시를 막는다. 작은 규모에서 별도 소켓 서버·브로커 운영을 줄이는 선택이다. 단체방에 연락처·Instagram·제외 관계는 게시하지 않는다.

푸시는 DB에 저장한 구독별 발송 작업으로 처리한다. 최초 포함 최대 3회, 실패 후 1분·5분 간격이며 반복 실패는 운영자 예외다. 권한 거부·미지원·미구독·서버 미설정을 전송 실패와 구분한다. 외부 전송은 별도 설정이 필요하며 가짜 공급자의 성공을 실기기 수신으로 기록하지 않는다.

## 영향과 검증

추가 스키마 0011을 격리 DB에서 검증한다. 배정·시스템 게시·앱 내 알림은 테이블 단위 원자적 트랜잭션이며 중복 Worker와 재실행에 안전해야 한다. 행사 종료 후 새 안내를 소급 생성하지 않는다. 운영의 기존 확정 데이터에 후속 처리가 실행되므로 배포·마이그레이션·운영 실행은 사용자 별도 승인을 요구한다. 실제 휴대폰 푸시는 별도 인수가 남는다.
