# 독립 합성 데모 참가자와 단계적 관심사 점수

> **2026-10-17 부분 대체:** 결정 2(매칭 목표)는 [ADR-0011](0011-prd-matching-score-and-objective.md)이 대체한다. 결정 1과 후속 B안은 유효하다.

2026-10-17 사용자 승인. 원본294개 응답의 계정 변환과 복합 가중치 설계 대신 다음 두 A안을 선택했다.

## 결정

1. 앱 데모에는 원본과 연결되지 않는 합성 참가자100명을 별도로 만든다. 원본은 ADR-0009의 비공개 준비 DB에 보존한다. 원본의 날짜·나이·누락 필드를 추정하거나 실제 참가 이력으로 사용하지 않는다.
2. 매칭 목표는 필수조건을 만족하는 **확정 인원 최대화 → 테이블 내 모든 두 사람의 공통 관심사 Jaccard 비율 합 최대화 → 기존 신청 순서**로 단계 구현한다. Jaccard는 공통 관심사 수/두 사람의 전체 관심사 수다. 성비·MBTI·성향·이력 반영과 최소 점수는 후속이며, 이 결정이 PRD의 모든 선호조건을 완료한다는 의미는 아니다.

## 이유와 범위

개인 개발·해커톤 일정에서 불확실한 원본 신원·날짜 보완을 피하고 시연을 반복 가능하게 한다. 관심사부터 시작하면 품질의 의미와 작은 입력 독립 정답을 설명하기 쉽다. 원본 분포를 그대로 반영한 데모나 전체 선호조건을 한 번에 가중합으로 구현하는 안은 추가 정책·검증 비용이 크다.

합성 참가자는 예약된 로그인 접두사와 결정적 ID, 합성임을 명시한 프로필로 구분한다. 초기 값은 모두 생성 값이며 이후 화면에서 수정한 값은 재실행으로 덮어쓰지 않는다. 자동 동의·신청·결제·실제 연락은 생성하지 않는다. 전용 로컬 데모 DB에서 먼저 검증하며 사용자는 검증·PR 머지 후 Railway 심사용 운영 DB에도 넣을 의도를 재확인했다. 대상 확인·배포·백업 후 명시 실행하는 별도 운영 단계이며 현재 운영 적재·자격 증명 전달은 미완료다.

관심사 최적화의 알고리즘·탐색 한도·최적성 보장과 실행 버전은 구현 계약에서 구분해야 한다. 현재 인원 중심 DP가 관심사 점수의 전역 최적성까지 보장한다고 확장 해석하지 않는다.

## 후속 B안 승인: 별도 합성 시연 기록

같은 날 사용자는 운영 데모 초기 상태로 B안(별도 합성100명 동의·신청·모의 결제 시나리오)을 추가 승인했다. 계정/프로필 시드는 계속 이러한 기록을 만들지 않고, [별도 명시 시나리오](../design/synthetic-demo-scenario-contract.md)가 기존 앱 API를 통해 준비한다. 기본 심사용4계정은 처음부터 체험하도록 유지한다. 기록이 없는 합성 동의만 생성하고 기존 거절/철회는 덮어쓰지 않는다. 회차 시간이나 매칭을 강제로 바꾸지 않으며 개별 API의 부분 완료를 안정된 요청 키로 재개한다. 실제 동의·실제 매출·원본 참가 이력으로 해석하지 않는다.
