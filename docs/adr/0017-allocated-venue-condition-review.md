# ADR-0017: 배정 후 식사 조건 변경 재검토

- 상태: 사용자 승인(2026-10-20), 구현·격리 검증 진행 중
- 위치: 모임 안내·피드백·재방문 → 식당·채팅·알림 → 배정·단체방·예약 메시지 구현. 감사 A3 보완이며 신규 Work/Task는 추가하지 않는다.

식당 배정 뒤 알레르기·못 먹는 음식·허용 식비가 마지막 적합성 확인 시점과 달라지면 운영자 재검토 예외로 표시한다. 기존 확정·식당·예약은 자동으로 변경하지 않는다. 현재 조건을 운영자가 확인해야 해소하며, 가격 조건 불충족은 확인 버튼으로 우회하지 않는다. 자동 재배정이나 참가자 권리 변경은 이 승인에 포함하지 않는다.

프로필 저장에 식당/테이블 잠금을 추가하지 않고 기존 worker가 예정·진행 중 테이블에서 감지한다. 테이블 → 프로필 공유 잠금 순서로 현재 조건을 읽는다. 별도 조건 digest는 마지막 확인 기준이며 과거 배정의 누락값을 현재 프로필로 소급 확정하지 않는다. 누락 기준은 재검토 대상으로 표시한다. 종료된 모임은 소급 처리하지 않는다.

확인은 기존 운영자·CSRF 경로를 사용해 최신 digest, 현재 배정 식당, 전원 허용 가격대와 좌석을 검사한다. 확인·기준 갱신·예외 해소·감사는 같은 트랜잭션이다. 일반 예외 메모만으로 해소할 수 없다. 음식 원문·변경자를 방/푸시/감사 본문으로 보내지 않는다.

현재 조건 비교이므로 worker 사이에 A→B→A로 돌아와 현재 조건이 동일하면 별도 변경 사건을 만들지 않는다. 모든 편집 사건 추적은 승인 범위가 아니다. 운영 migration·배포·운영 데이터 변경은 실행하지 않는다.
