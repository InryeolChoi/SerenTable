# 에이전트 공통 기록 갱신 절차

저장소에서 작업하는 에이전트가 직접 수행한다. 사용자의 별도 “문서 갱신” 요청을 기다리지 않는다. 작업 결과에 영향을 받는 기록만 고치며, 변경이 없는 문서는 유지한다.

## 언제, 무엇을 갱신하는가

| 발생한 변경 | 갱신할 기준 문서 |
|---|---|
| Task 결과, 검증 완료, 중단 또는 도구 전환 | [HANDOFF.md](HANDOFF.md): 기준 시각, Agenda → Work → Task, 브랜치/PR, 검증 환경·명령·결과, 미완료, 다음 행동, 사용자 미커밋 변경 |
| 사용자가 확정한 요구·정책 또는 미결정 항목 해소 | [구현 명세](../design/mvp-implementation-spec.md)의 해당 항목과 관련 ADR. 결정 이유·대안·영향은 ADR에 기록 |
| 도메인 용어 또는 그 의미 변경 | [GLOSSARY.md](../../GLOSSARY.md), 해당 용어를 사용하는 명세/설계 |
| 데이터 관계·상태 전이·무결성 제약 변경 | [핵심 데이터 모델](../design/core-data-model.md)과 영향받는 ERD 원문/시각 자료. 생성 절차를 확인하고 그림·링크를 검증 |
| 화면·브랜드·권한·운영 절차 변경 | 해당 UI·브랜드·보안 설계 또는 운영 지침. 실제 구현·시험 결과와 설계 목표를 구분 |
| Task 진척·인수 기준·검증 증거 변경 | 기존 GitHub Issue/PR의 해당 내용과 연결 문서. [이슈 운영](issue-tracker.md)에 따라 부분 완료와 전체 완료를 구분 |
| 공통 작업 방식 변경 | 루트 [AGENTS.md](../../AGENTS.md) 또는 이 절차. 도구별 진입 파일은 참조만 유지 |

위 링크의 문서가 현재 브랜치에 없으면 관련 Task PR에서 확인한다. 승인된 결정을 추측으로 보충하지 않는다. 요구사항의 제안·사용자 승인·구현·검증을 각각 표시한다.

## 종료 전에 수행할 순서

1. 현재 작업의 실제 변경과 검증 결과를 확인하고 위 표에서 영향을 받는 문서를 갱신한다. 현재 Task의 기준 문서가 어디인지 인계 기록에서 찾을 수 있게 한다.
2. 실제 Git 상태와 접근 가능한 GitHub Issue/PR 상태를 대조한다. 인계 기록은 기준 시점의 관찰이며 파일에 자기 자신의 최종 커밋 해시를 맞추기 위해 후속 커밋을 반복하지 않는다.
3. 수정한 문서의 링크·참조·그림과 구현의 일치 여부, 공개할 정보의 비밀값/개별 응답 포함 여부를 확인한다. 사용자 미커밋 파일은 작업 변경과 분리해 보존한다.
4. 기존 Issue/PR에 필요한 결과·검증·미완료를 반영한다. 접근 권한이나 연결이 없으면 저장소 기록을 먼저 완료하고 미반영 위치와 복사할 문구를 사용자에게 제공한다. 실행하지 않은 외부 갱신은 완료로 표시하지 않는다.
5. 사용자에게 현재 Task의 결과와 실제 PR 링크를 제시한다. Blaybus에는 정확한 Agenda → Work → Task, 붙여 넣을 수행/검증 문구, 권장 상태를 제공한다. 실제 작업 시간은 사용자가 입력한다.

완료 기준은 관련 문서 갱신, 수행한 검증의 증거, 남은 항목, 외부 반영 결과를 다음 에이전트가 찾을 수 있는 상태다. PR 머지·배포·사업 정책 확정은 각각 기존 사용자 승인 범위와 인수 기준을 따른다. 기록 갱신 지침 자체가 그 범위를 확대하지 않는다.

## 도구를 바꿀 때

- 다음 에이전트는 AGENTS.md → HANDOFF.md → 현재 Task에 필요한 문서 순서로 읽고 실제 저장소 상태와 대조한다.
- 자동 지침 로딩을 지원하지 않는 도구에는 다음 문구를 첫 요청에 포함한다: “AGENTS.md와 docs/agents/HANDOFF.md를 먼저 읽고, docs/agents/record-maintenance.md에 따라 작업 결과와 인계 기록을 스스로 갱신해 주세요.”
- 대화 이력·로그인·MCP·스킬 등록은 별도다. 현재 도구에서 확인된 접근 범위를 인계한다.
- 예고 없는 프로세스 종료나 사용량 제한 후에는 추가 기록을 보장할 수 없으므로 긴 작업은 주요 단계마다 저장한다. 재개 시 실제 파일과 Git을 확인해 마지막 기록 이후의 차이를 복구한다.
