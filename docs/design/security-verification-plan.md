# 개인정보·권한·보안 검증 기준

**Work #6 실패 해결 보완:** 참가자 POST 해결/보관권 재사용은 기존 세션·CSRF·participant 권한을 사용한다. 타인 신청/권리는 404, 운영자는 403이며 상태 오류에 연락처·Instagram·다른 참가자·점수/제외 관계를 노출하지 않는다. 현재 실패 실행·남은 후보·미사용 권리·현재 예약·원결제 PAID·확정/시간 겹침을 잠금 후 재검사한다. 요청 키와 실패 실행의 일의성, 공통 매칭 잠금, 예약 UNIQUE를 함께 사용한다. GET 및 오류는 no-store. 모의 환불은 실제 계좌·카드·PG 정보 없이 처리한다. [실행 증거](./matching-resolution-contract.md)는 설계 목표와 실제 시험을 구분한다.


**후속 합성 시나리오 B안:** 별도 명시 CLI만 합성100명의 동의·신청·모의 결제를 앱 API로 준비한다. 합성 ID/정책/mock 상품 확인, 혼합 회차·기존 동의 거절의 사전 중단, 고정 요청 키 재개, 환경 프록시·redirect 금지·세션 정리 예산을 적용한다. 기본 심사용 계정과 원본은 사용하지 않는다. [계약](./synthetic-demo-scenario-contract.md). 실제 운영 적재는 머지·배포·백업 후이며 현재 로컬 시험과 구분한다.

**2026-10-17 합성 앱 시드:** 원본 비연결 합성100명 계정·프로필만 생성하고 자동 동의/거래는 만들지 않는다. 기본 로컬 전용 DB와 명시 Railway 모드를 구분하며, 후자는 프로젝트·환경·API 서비스 ID·private DB 대상·실행별 opt-in을 확인한다. 잘못된 ID/worker/query/libpq 우회와 암묵적 production 실행을 거부한다. 비밀번호·기존 프로필/활성 상태는 재실행으로 덮어쓰지 않고 중간 오류는 전체 롤백한다. [계약](./synthetic-demo-seed-contract.md). 운영 형식 확인만 수행했고 실제 운영 적재는 아직 아니다.

**2026-10-17 원본 준비 CLI:** 원문 전체·가명/연락처·자유 입력을 복제하거나 출력하지 않고 집계만 반환한다. 준비 영역에 공개 API가 없으며 CLI는 별도 loopback 준비 DB만 허용하고 앱 DB·원격·production 실행을 거절한다. source_private는 PUBLIC 권한을 제거했고 실제 비권한 역할의 조회 거절을 시험한다. 소유자 권한에는 적용되지 않으므로 schema만으로 현재 운영 DB 소유자 앱 역할과 분리됐다고 주장하지 않는다. 별도 로컬 DB/연결이 실제 격리 수단이다. [상세](./source-preparation-contract.md).

**2026-10-17 추가 경계:** 대체 일정 조회는 로그인한 참가자의 본인 SUBMITTED·NO_MATCH 신청만 허용한다. 타인/없는 ID의 동일 404, 운영자 403·익명 401, no-store를 실제 PostgreSQL HTTP에서 확인했다. 응답은 공개 회차 메타데이터만 포함하며 다른 신청자·개별 점수·개인정보를 포함하지 않는다. 읽기 요청은 신청/후보/결제/권리/매칭 상태를 변경하지 않는다. 전체 보안 인수와 실제 기기 검증을 완료한 것은 아니다.

**Task:** 개발·배포 기반 확보 → 핵심 데이터·화면·보안 설계 → 개인정보·권한·보안 검증 기준 정리

**추적:** [Task Issue #19](https://github.com/InryeolChoi/SerenTable/issues/19), [Work Issue #15](https://github.com/InryeolChoi/SerenTable/issues/15)

**기준일:** 2026-10-16, Asia/Seoul. 보안 설계와 읽기 전용 현황 점검 산출물이다. 인증·업무 데이터·보안 기능을 구현하거나 배포 안전성을 인증한 결과가 아니다.

## 신뢰 경계와 권한 판정

역할 이름만으로 허용하지 않는다. 서버가 인증된 주체, 객체 소유자, 신청·확정 상태, 현재 유효한 테이블 배치와 채팅 멤버십, 실행하려는 행동을 함께 확인한다. 브라우저 버튼 숨김은 보조 표시이며 API의 승인 근거가 아니다. 새 기능은 허용 규칙이 없는 경우 거절한다. 이는 [OWASP 권한 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)의 기본 거절·매 요청 검증 원칙을 이 서비스에 적용한 제안이다.

ERD의 `Application → ApplicationCandidate → MatchParticipation → TableAssignment`를 따라 소유권과 참가 범위를 확인한다. 동의한 회차 후보에 속한다는 사실만으로 확정 참가자나 채팅 멤버가 되지 않는다. 이전 회차의 `TRANSFERRED` 기록도 새 회차의 권한을 주지 않는다. 물리 테이블·토큰 형식은 이 문서에서 동결하지 않는다.

| 주체 | 의미·판정 근거 |
|---|---|
| 익명 | 유효한 인증이 없는 방문자. 모집 공개 정보와 로그인 안내만 접근 |
| 본인 | 세션 주체가 요청 객체의 사용자와 같은 참가자 |
| 타인 | 다른 참가자. 같은 회차 신청 여부만으로 공개 범위가 넓어지지 않음 |
| 동일 테이블 | 서버에서 현재 유효한 확정 배치와 방 접근권을 확인한 참가자. 본인 객체 권한과 별개 |
| 운영자 | 서버가 부여한 운영 권한. 요청의 `role=admin`이나 화면 주소로 생성되지 않음 |
| 실행기 | 인증된 사람 계정이 아닌 제한된 업무 실행 주체. 예약 작업·알림·매칭에 필요한 데이터만 사용 |

### 객체별 조회·변경 권한안

`조회`는 허용 필드만 읽는다는 뜻이다. `행동`은 정해진 상태 전이 명령이며 임의 상태값 수정이 아니다. `제안`인 운영자 범위와 상세 정책은 해당 Work에서 승인한다.

| 객체·행동 | 익명 | 본인 | 타인 | 동일 테이블 | 운영자 | 실행기 |
|---|---|---|---|---|---|---|
| 모집 회차·공개 식당 설명 조회 | 공개 설정분 | 동일 | 동일 | 동일 | 설정·조회 | 배정용 조회 |
| User·Profile·동의 | 거절 | 본인 조회·허용 필드 수정·동의 기록 | 거절 | 승인된 소개 필드만 | 목적에 필요한 조회, 임의 동의 대행 거절 제안 | 매칭 필요 입력만 조회 |
| Application·후보·MatchParticipation·미매칭 해결 | 거절 | 본인 조회·신청/선택/취소 행동 | 거절 | 타인 신청·실패 사유 거절 | 운영 현황·예외 행동, 감사 기록 | 허용 상태 전이·후보 처리 |
| 이용권·모의 결제·환불 | 거절 | 본인 조회·결제/환불 요청 | 거절 | 거절 | 업무 조회·승인된 예외 행동 | 예약된 모의 처리·재시도 |
| DiningTable·TableAssignment·결과 설명 | 거절 | 본인 결과만 | 거절 | 확정 결과·제한 소개 | 실행·예외·상세 원인 조회 | 조합·재검증·확정 |
| ChatRoom·메시지 | 거절 | 유효한 방 권한이 있을 때 조회·발송 | 거절 | 해당 방 조회·본인 메시지 발송 | 업무상 열람 범위 미정, 기본 거절 제안 | 정해진 시스템 게시만 |
| Notification·푸시 구독 | 거절 | 본인 목록·본인 기기 등록/해지 | 거절 | 거절 | 전달 상태·실패만 조회 제안 | 대상별 발송·결과 기록 |
| Attendance·Feedback | 거절 | 자격·시점 충족 시 본인 제출·조회 | 거절 | 타인 평가·선호 거절 | 업무 집계·노쇼 후보·예외 조회 | 시점 판정·리마인드·다음 매칭 입력 |
| SafetyReport·비선호/차단 | 거절 | 본인 제출·허용된 처리 상태 조회 | 거절 | 피신고자 포함 타인 내용 거절 | 검토·승인된 조치와 이력 | 필요한 제외 관계만 조회, 신고 원문 불필요 |
| ExceptionCase·감사·CSV | 거절 | 본인에게 허용된 요약만 | 거절 | 거절 | 범위 제한 조회·예외 처리·내보내기 | 처리 결과 추가, 감사 삭제 거절 |
| 시드·초기화·마이그레이션 | 거절 | 거절 | 거절 | 거절 | 일반 운영 화면에서 거절 제안 | 배포 실행기와 구분된 승인된 운영 명령만 |

동일 테이블 권한의 시작은 확정과 유효한 멤버십 둘 다 충족하는 시점이다. 취소·차단·탈퇴 후 과거 메시지 열람/퇴장 시점은 U04/U09/U11/U16을 승인해야 한다. 승인 전에는 새 대상의 자료를 넓혀 공개하지 않으며, 관련 기능을 완료로 처리하지 않는다. 역할별 범용 권한 엔진이나 여러 관리자 등급을 새로 만들 필요는 없다.

### 필드 공개·수정 기준안

| 필드 묶음 | 본인 | 타 참가자·동일 테이블 | 운영자·실행기 | 수정 경계 |
|---|---|---|---|---|
| 이름·연락처·Instagram ID | 본인 조회 | 확정 전 비공개. 확정 후 표시명 형식도 U16 승인 대기. 연락처/Instagram 자동 공유 금지 제안 | 운영 목적에 필요한 범위, 실행기는 연락 목적이 없는 경우 제외 | 본인 허용 입력만; 계정 주체 변경과 분리 |
| 출생연도·성별·직업·MBTI·관심사·성향 | 본인 조회 | 확정 후 소개 항목·연령 표시 수준 U02/U16 승인 대기 | 매칭·운영 필요 필드 | 검증된 입력 계약; 수정 후 확정 결과 영향은 기능 정책 적용 |
| 음식·알레르기·가격대 | 본인 조회 | 개인별 원문 공유 금지 제안 | 식당 배정에 필요한 범위 | 빈 음식 값을 안전/알레르기 없음으로 변환하지 않음 |
| 결제·이용권·환불·기기 푸시 endpoint | 본인 허용 정보 | 비공개 | 업무 주체별 필요한 범위 | 참가자는 `PAID`·잔액·환불 완료를 직접 지정하지 못함 |
| 사람별 피드백·차단·신고 원문/신고자 | 본인 제출 기록의 허용 범위 | 상대방 포함 비공개 | 안전 담당 운영자, 실행기는 필요한 제외 관계만 | 타인 원문·제출자를 수정하거나 추정할 응답 금지 |
| 점수·제외 쌍·내부 예외·스택·DB URL | 본인 결과의 일반 설명만 | 비공개 | 승인된 운영 요약, 실행에 필요한 내부 데이터 | 일반 요청 입력으로 변경 불가 |
| 사용자 역할·소유자 ID·테이블 확정·감사 이력 | 본인 허용 상태 조회만 | 제한된 결과만 | 업무 명령으로만 변경·추가 | mass assignment 거절; 역할·소유자·생성시각을 요청에서 신뢰하지 않음 |

전체 ORM 객체를 응답한 뒤 UI에서 숨기지 않는다. 본인·소개·운영 조회의 응답 허용 필드를 나누고 목록·상세·CSV·채팅 이력·알림 payload에 같은 기준을 적용한다. 참가자의 실패 이유에 특정 차단 상대·신고 존재·개별 점수를 포함하지 않는다. 서버의 총계·오류 메시지에서도 타인의 객체 존재를 불필요하게 알려주지 않는다.

## 기능별 거절·무결성 검증 계획

**합의된 주 경계:** 실제 PostgreSQL과 API·별도 worker의 외부 행동이다. 계정 A(소유자), B(타인), C(확정 동일 테이블), D(다른 테이블), O(운영자), 만료·비활성 계정을 합성 fixture로 준비한다. 필요한 사실은 공개된 생성/조회 계약과 독립 fixture로 확보한다. 내부 ORM·함수 호출 횟수·DB 직접 조회로 권한 성공을 대신하지 않는다.

각 기능은 우선 한 허용 흐름과 가장 위험한 거절 사례를 실패 테스트로 만들고 구현한다. 아래 전체 표를 한꺼번에 가상의 API 테스트로 작성하지 않는다. 미정 URL·정책은 해당 Work 시작 시 확정한다.

| Work | 최소 실행 사례 | 외부에서 관찰할 통과 기준 |
|---|---|---|

## 2026-10-18 Work8·9 구현 검증 경계

ADR-0014의 신고 즉시 쌍 분리·기각 후 유지·상호 재만남 점수 면제와 U15 체크인 창을 따른다. 선호/신고 응답은 본인 입력과 상대 표시명만 노출하고 상대방에게 신고 존재를 알리지 않는다. 활성 제재는 새 신청·추천에서 검사한다. 신고·차단·선호 변경은 자동 매칭과 같은 공용 잠금→행 잠금 순서로 처리하며 실제 PG 두 연결 경합5개를 실패 재현 후 통과했다.

운영자 변경·감사는 같은 트랜잭션으로 커밋·롤백한다. 대시보드는 숫자, CSV는 허용된 내부ID·표시명·상태만 사용한다. CSV의 현재 배정 수와 명단을 같은 집합으로 계산하고 = / + / - / @ 및 탭·CR로 시작하는 셀을 방어한다. API 역할·CSRF·감사 실패 롤백과 모바일 운영자 화면 접근 거절을 검증했다.

2026-10-19 승인된 [ADR-0015](../adr/0015-operator-failure-recovery.md)에 따라 모의 환불 실패 기록·운영자 멱등 재시도와 대안 미응답 표시를 연결한다. 미응답은 원래 실패 회차 시작 시각을 지난 경우의 운영 표시이며 참가자의 이동·보관·환불 권한을 자동 종료하지 않는다. 모의 환불의 금융 저장 단계가 실패하면 결제 PAID·이용권 예약을 보존하고 재매칭·재사용을 막는다. 운영자 재시도에는 역할·CSRF 검사와 원결제·금액·미사용 권리 재검사를 적용한다. 실패 기록·감사·최종 커밋 단계의 장애는 전체 롤백하며, 저장할 수 없는 실패를 영속 기록했다고 표시하지 않는다. 실제 PG 호출이나 공개 실패 버튼은 제공하지 않는다.

격리 PostgreSQL의 HTTP 시험으로 금융 저장 실패·같은 키 재전송·동시 재시도·권한 거절·감사 실패와 지연 커밋 오류의 롤백을 검증한다. 이는 로컬 합성 시험 경계이며 운영 마이그레이션·배포·공개 환경 인수를 대신하지 않는다. 기존 Work8·9 실행 증거는 [검증 기록](work8-work9-verification-2026-10-18.md), 후속 복구 결정은 ADR-0015와 해당 PR의 최신 검증 기록을 기준으로 구분한다.

감사 보관 기간(U16), 역할 세분화, 기존 운영 조치 전반의 사유 필수화는 여전히 미정이며 이번에 구현하지 않는다. 사용자 입력 메모의 운영상 개인정보 통제·삭제 요청 운영을 실제 개인정보 수집 승인으로 확대하지 않는다. 실제 휴대폰 푸시와 운영 인수는 미검증이다.
