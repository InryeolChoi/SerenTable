# 2026 우연한 식탁 MVP 해커톤 — 킥오프 기록

## 출처와 사용 원칙

2026년 10월 14일(Asia/Seoul) 온라인 킥오프에서 직접 들은 내용으로 사용자가 전달한 기록을 읽기 쉽게 정리했다. 공식 PRD를 보완하는 현장 기록이며 공식 수정 공지가 아니다. PRD와 차이가 있는 요구사항은 임의로 삭제하거나 변경하지 않는다. 운영 실적은 집계 기간과 수치를 자료별로 구분한다.

## 서비스와 현재 운영

- 서비스: 우연한 식탁. 운영사: 와썹하우스. 해커톤 운영: 블레이버스.
- 서로 모르는 4~6명을 연결하는 소셜다이닝 서비스. 자연스러운 만남의 계기 부족을 해결한다.
- 동호회의 지속 참여 부담, 소개팅의 연애 목적 부담, 대규모 모임의 낮은 대화 밀도, 랜덤 만남의 안전·품질 불확실성을 문제로 설명했다.
- 대표님은 유사성 효과와 오찬 효과를 기획 근거로 설명했다. 성향·관심사에 따른 매칭과 함께 식사하는 경험, 이력·피드백에 따른 장기적인 품질 개선을 지향한다. 효과의 과학적 검증을 이 기록에서 주장하지 않는다.
- 현재 Google Forms 신청 → 문자·입금 확인 → Excel/Spreadsheet 수기 매칭 → 네이버 식당 예약 → 카카오톡 오픈채팅 → 개별 연락 → 개별 피드백 관리로 운영한다.
- 매칭 조건 복잡성, 운영 리소스 증가, 개별 확정·연락 시간, 취소·노쇼, 분산된 피드백, 대기·실패·환불 설명이 운영 문제다.
- 대표님이 가장 불편하다고 설명한 업무: “참가자를 일일이 확정하고 각 참가자의 연락처로 개별 안내하는 과정”.
- 핵심 목표: 신청 → 결제 → 자동 매칭·확정 → 식당 배정·안내 → 식사 → 피드백 → 다음 추천의 정상 흐름을 운영자 개입 없이 끝내고 해결 불가능한 예외만 어드민에 표시한다. 화면 수보다 E2E 완주가 중요하다.

## 사용자가 전달한 Q&A

### 플랫폼과 기술

- 반드시 네이티브 앱인가? **웹앱도 가능하다.**
- Android/iOS 모두 지원해야 하나? **둘 중 하나만 제공해도 된다.**
- 기술 스택 제한? **없다.**
- 외부 MCP 도구 사용? **자유롭게 사용할 수 있다.**
- 참가자·관리자 웹페이지 제공? **가능하다.**
- 디자인 규칙? **자유롭게 설계할 수 있다.**
- 로고? **기존 우연한 식탁 로고를 사용하며 파일을 제공할 예정이다.**

### 데이터와 매칭

- 기존 참가 이력·피드백 데이터? **익명화된 데이터를 제공할 수 있다.** 실제 수령 여부·시점·스키마는 미확인이다.
- 인원이 부족하면? **가능하면 자동으로 다른 적합한 참가자와 연결되도록 구현하는 것이 좋다.** PRD의 자동 재배치 P0를 선택 기능으로 낮추지 않는다.
- 개인정보 항목? **이름, 직업, 나이 등이 있으며 추가 항목은 와썹하우스 인스타그램을 참고한다.** 필수 구현 항목은 PRD 기준이며 인스타그램은 아직 확인하지 않았다.

### 결제와 식당

- 기존 결제 플랫폼? **별도로 사용하지 않는다.**
- 실제 결제 연동 필수? **가상 결제 기능으로 구현해도 된다.**
- 가상 식당 등록? **가능하다.**
- 식당 예약 실패 처리? **이번 해커톤에서는 고려하지 않아도 된다.**
- 식당 예약 구현? **지역별 식당 목록이 존재한다고 가정하고 예약이 가능한 것으로 처리해도 된다.**

### 운영 및 제출

- 직원 수? **2명.**
- 한 달 서비스 운영비 예산? **현재 답변하기 어렵다.** 이 프로젝트에서 정한 월 3~5만원 예산은 사용자의 예산이며 운영사 예산이 아니다.
- 실제 출시 목표? **2026년 12월~2027년 1월.**
- 결과물 제출? **배포 링크 제출로 통일한다.**

## 평가·기록·제출

- 자동 매칭 25점, 모임 안내 20점, 피드백 반영 15점, 운영자 어드민 10점, 참가자 경험 10점, 도메인 이해 10점, 프로젝트 기록 10점. 총 100점.
- Blaybus Workspace에 Agenda/Work/Task, 실제 투입 시간, 진행 기록, 중간 산출물을 기록한다. 저장소 기록만으로 플랫폼 기록을 충족했다고 간주하지 않는다.
- 마감: 2026년 10월 21일 23:59. 제출 위치는 사용자 현장 기록에 따르면 Blaybus 프로그램 > 제출.
- 참가자 화면·운영자 어드민을 확인할 배포 URL, 필요 시 테스트 계정 제공. 같은 URL에서 이동 가능하면 링크 하나도 가능하다.
- 완주 기준은 마감일까지 접속 가능한 배포 링크 제출이다. 이는 PRD의 MVP 12단계 완료와 별개 기준이다.
- 공식 킥오프 슬라이드는 Output 탭 제출 메시지를 안내한다. 플랫폼에서 실제 제출 위치 확인이 필요하며 아직 불일치로 단정하지 않는다.

## PRD와의 차이 및 미확인 항목

- **식당 예약 실패**: Q&A는 생략 가능, PRD INF-02/§15는 재고 부족 시 대체 식당 탐색 후 예외 전환을 요구한다. 외부 예약 API 실패와 내부 재고 부족은 다른 상황이므로 분리해 인터뷰 Q6에서 범위를 확인한다.
- 웹앱·가상 결제는 기존 MVP 방향과 양립한다. 가상 식당 허용은 외부 예약 API가 필수라는 해석을 피할 근거다.
- 푸시·알림 재시도 생략, 자동 재배치 생략, 필수조건 완화는 이 Q&A에서 허용한 것으로 해석하지 않는다.
- 제공 예정 로고와 익명 데이터는 아직 수령하지 않았다. 핵심 개발의 선행 조건으로 둘지 추후 판단한다.
- 사용자 제공 현장 기록을 사실 출처로 보관했으며, 외부 공식 답변 원문과 대조한 것은 아니다.
