# PRD·구글폼·킥오프 요구사항 대조

**Task:** 개발·배포 기반 확보 → 요구사항·설계·자료 정리 → PRD·구글폼·킥오프 차이 기록
**대조일:** 2026-10-15 (Asia/Seoul). 문서 원본 감사 보강이며 제품 기능 완료를 뜻하지 않는다.

| 기호 | 자료 | 확인 범위 |
|---|---|---|

| D | [설계 인터뷰](./mvp-interview.md), 승인된 ADR | 제품 구현 방향에 대한 사용자 결정. 원본 PRD 문구와 구현 선택을 구분한다. |

제품 요구의 기준은 **PRD**이다. 현행 폼은 현재 수작업 운영의 관찰 자료이며 화면 안 문구를 앱 구현 지시로 취급하지 않는다. 킥오프 Q&A는 허용 범위의 보완 근거로 사용하고 PRD P0를 자동 삭제하는 근거로 사용하지 않는다. 이미 확정한 결정은 다시 질문하지 않으며, 후속 정책은 [구현 명세서의 U01~U20](./mvp-implementation-spec.md#further-notes-추가-사항)에서 추적한다.

## 입력·상품·개인정보 차이

| 항목 | 원본 근거 | 대조 결과와 적용 기준 |
|---|---|---|
| 기본 정보 | P p.4 ACC-02; U | PRD는 이름·연락처·출생연도·성별·직업 입력·수정, U는 나이를 열거한다. PRD의 출생연도를 유지한다. 나이 기준일·변환·표시는 U02이며 화면에서 출생연도 입력을 관찰한 것으로 쓰지 않는다. |
| Instagram ID | P p.4 ACC-02, p.10 §13; U | PRD 목록에 없고 사용자가 추가 수집을 요청했다. 추가 항목으로 보존하되 필수성·목적·공개 범위는 U02/U16이다. 매칭 점수나 타 참가자 공개를 승인한 것은 아니다. |
| MBTI 입력 | P p.4 ACC-03; F4 | PRD는 MBTI·관심사·본인/상대 성향을 복수 선택할 수 있다고 서술한다. 현행 화면의 MBTI는 필수 자유 입력처럼 보인다. 단일 MBTI로 임의 축소하거나 자유 입력을 그대로 채택하지 않으며 입력 계약은 U02이다. |
| 관심사 분류 | P p.4 ACC-03; F4; U | P는 구체 목록을 정하지 않는다. F4는 독서·글쓰기를 합친 10개, U는 분리한 11개다. 사용자 요청 11개를 기록하되 기존 통합 응답을 독서와 글쓰기 둘 모두로 추정하지 않는다(U17). |
| 본인·상대 성향 | P p.4 ACC-03, p.5 MAT-04; F3 | 두 화면 모두 복수 선택·필수다. 본인 성향 6개와 상대 선호 6개는 동일 어휘 집합이 아니다. 선호 해석·대응표는 U05이며 문자열 교집합을 궁합 점수로 확정하지 않는다. |
| 식사 조건 | P p.4 ACC-04; F1 | 가격대·못 먹는 음식 수집은 공통이다. P는 알레르기도 명시하지만 F1에 별도 알레르기 항목은 보이지 않는다. 알레르기를 생략하지 않는다. 가격 선택지의 20,000원 경계 중첩과 ‘30,000원 이상(상관 없음)’ 해석은 U10이다. |
| 지역 | P p.4 APP-02; F1 | 둘 다 복수 선택이다. 폼에는 홍대/합정·잠실·강남/신논현·을지로/종로·기타가 있다. PRD가 이 목록으로 지역을 고정한 것은 아니다. 자유 입력을 즉시 매칭 가능한 표준 지역으로 추정하지 않는다(U17). |
| 날짜 | P p.4 APP-01/02; F2 | 폼은 10/15·10/22·10/29·11/5 단일 선택, PRD는 모집 날짜·시간·지역·마감 확인 및 날짜 복수 선택이다. **PRD 복수 선택을 유지**하며 폼의 날짜를 앱 고정 회차로 사용하지 않는다. |
| 이용권 | P p.4 APP-04; F2; D Q14 | 폼의 1회권 8,000원·3회권 15,000원/2개월·잔여권 사용과 P의 1회권·구독 이용권은 다르다. **1회권 + 모의 구독**으로 확정했다([ADR-0007](../adr/0007-prd-ticket-scope.md)). 3회권 자동 추가와 실제 정기 청구는 제외하며 구독 기간·한도·갱신은 U03이다. |
| 개인정보 동의 | P p.4 ACC-05, p.7 INF-06, p.11 §16; F2 | P는 개인정보 수집·이용과 운영 정책 동의를 신청 조건으로 요구한다. F2의 단톡방 안내는 보이지만 동의 선택지가 아래에서 잘려 있다. 해당 문구만으로 앱의 동의 항목·보관 기간·공개 범위가 정의됐다고 간주하지 않는다(U16). |
| 단체방 퇴장 | P p.1 환불 규정; F2 | P는 당일 취소 및 단체 채팅방 퇴장 불가, F2는 식사 후 퇴장해도 무방하다고 안내한다. 표현상 차이가 있으며 정확한 퇴장 허용 시점은 U04이다. 현행 카카오 오픈방의 안내로 앱 단체방 정책을 덮어쓰지 않는다. |

| 웹앱·테스트 계정 | P p.4 ACC-01, p.11 §16; K 플랫폼 Q&A | 테스트 계정 로그인과 모바일 우선 화면은 PRD에 있다. K는 참가자·관리자 웹페이지와 웹앱을 허용한다. React CSR·FastAPI는 사용자 기술 결정이며 PRD가 특정 프레임워크를 요구한 것은 아니다. |

## PRD 내부의 후속 해석 항목

다음은 폼이나 Q&A의 변경 요구가 아니라 **PRD 자체 문구 사이의 해석 경계**이다. 기존 명세의 미결정 항목을 그대로 연결한다.

| 항목 | 상충·해석 근거 | 추적 |
|---|---|---|
| 최소 점수·가중치 설정 | P p.6 §7.0은 자동 확정에 운영자 설정 최소 점수 이상을 요구한다. p.5 MAT-10은 필수조건·인원 충족으로 서술하고 MAT-15의 설정 기능은 P1이다. 최소 점수를 임의 삭제하거나 설정 UI 전체를 새 P0로 확정하지 않는다. | U05, U14 |
| 확정 후 취소 | P p.11 §15는 자동 충원·재배치를 요구한다. p.5 STA-07 대기자 전환과 MAT-14 긴급 수정은 P1이다. | U13 |
| 신고 관계 제외 | P p.5 MAT-05는 ‘신고 확정 관계’, p.5~6 §7은 신고 관계, p.11 §15는 신고 발생 시 향후 매칭 즉시 분리를 서술한다. | U09 |
| 체크인 시점 | P p.8 FDB-01은 종료까지 미체크인을 노쇼 후보로 정의하지만 p.12 §18 단계 10은 ‘행사 후’ 체크인을 서술한다. | U15 |
| 실패 환불과 제한 | P p.4 PAY-02는 진행 2일 전 이후 제한, PAY-03과 p.11 §15는 매칭 불가 시 선택에 따른 자동 환불이다. 일반 취소 제한과 시스템 매칭 실패의 적용 관계·시각은 아직 미정이다. | U04 |

## 검증 결과와 남은 일

- PRD 12쪽 전체를 텍스트로 읽고, ACC/APP/PAY 원문 표(p.4), 안내 표(p.7), 예외·비기능(p.11), 완료 시나리오(p.12)를 렌더링하여 페이지와 표 대응을 확인했다.
- 공식 킥오프 24쪽 전체 텍스트에서 평가·일정·기록·제출을 대조했고 제출 안내 p.19~20을 렌더링해 확인했다. p.19 안의 작은 예시 화면에 있는 다른 프로젝트의 PDF/PPT 제출 문구를 이번 해커톤 제출 요구로 옮기지 않았다.
- 첨부 폼 화면의 관찰, 사용자의 추가 설명, 공식 PRD, 구두 Q&A 기록, 승인된 구현 결정을 분리했다. 원본 PDF·이미지는 수정·복사·커밋하지 않았다.
- 상품·식당 범위의 이미 승인된 결정을 재질문하지 않는다. 위 U 항목은 기존 후속 Work에서 결정하며 이 문서 Task를 위해 새 Work·Task를 추가할 필요는 없다.
- 이 감사는 출처와 요구사항 추적을 검증하므로 런타임 코드를 추가하거나 제품 테스트 통과를 주장하지 않는다. 폼 원본 파일의 재확인과 실제 제출 화면 경로 확인은 남아 있다.
