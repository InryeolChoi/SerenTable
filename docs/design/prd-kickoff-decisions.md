## 1. 요약

### (A) 확정된 것 (10줄)

1. 필수조건: 결제 완료, 참가 가능 날짜·희망 지역 일치, 한 테이블 4~6명, 연장자–막내 나이 차이 8살 이내, 차단·신고·비선호 관계 없음 (PRD p.5~6 §7.0).
2. 필수조건은 재배치 중에도 완화 금지, 4명 미만은 "절대 확정하지 않는다" (PRD p.6 §7.3, p.7 §7.4). FAQ Q6도 "필수조건은 완화하지 않는다" (FAQ:L26).
3. 선호 평가 순서(PRD 기능표): 연령대 → 성비 → MBTI 궁합 → 관심사 → 만나고 싶은 사람 (PRD p.5 MAT-04). 새로운 사람 우선이 별도 P0 (PRD p.5 MAT-06).
4. 선호조건은 "조건별 점수를 합산해 가장 좋은 조합 선택", 자동 확정 기준은 "필수 조건 전체 충족 + 운영자가 설정한 최소 매칭 점수 이상" (PRD p.6 §7.0).
5. 재배치 순서 4단계(같은 날짜·같은 지역 → … → 다른 날짜·다른 지역) 뒤 범위 밖 일정은 동의 후 이동, 그다음 보관/환불 (PRD p.7 §7.4).
6. 정상 흐름은 운영자 검수 없이 자동 확정 (PRD p.2 §1, p.5 MAT-10). FAQ Q10 재확인 (FAQ:L30).
7. 성비는 선호조건, 공식 MBTI 궁합표 없음 (FAQ:L27~28).
8. 이용권: 1회권 9,900원, 멤버십 1/3/6개월 35,000/75,000/120,000원, 기간 내 무제한, 매칭 실패 횟수만큼 기한 연장 (FAQ:L24~25).
9. 모바일 웹앱 허용(참가자 화면은 설치 없는 모바일 웹앱, 링크 심사), 가상 결제·가상 식당 허용 (FAQ:L20, K:L22·L39~42).
10. 심사 배점: 자동 매칭 25 · 모임 안내 20 · 피드백 반영 15 · 어드민/참가자 경험/도메인/기록 각 10, 마감 10/21(수) 23:59 (슬라이드 p.7, p.6, p.20).

### (B) 정하지 않은 것·모호한 것 (10줄)

1. 점수 가중치·점수표·최소 매칭 점수 값·목적함수·탐색 알고리즘: 1차 출처 어디에도 수치가 없다. 운영자가 설정하는 값으로만 정의돼 있다 (PRD p.6 §7.0, p.5 MAT-15 P1).
2. **인원 최대화 vs 품질 우선**: 1차 출처에 명시가 없다. PRD는 "전체 조합을 최적화"한다고만 쓴다 (PRD p.6 §7.1-6).
3. **선호 우선순위 순서가 출처마다 다르다**: PRD MAT-04는 연령대 1순위, CTO p.8은 성비 1순위로 시작하고 연령을 soft score에서 뺐다.
4. "연령대" 선호가 8살 상한(필수)과 별개의 점수 항목인지 모호하다 (PRD p.1 "1순위: … 나이 차이 최대 8살" vs p.5 MAT-03/MAT-04).
5. 관심사 유사도 계산식(Jaccard 등), MBTI 궁합 기준, 성향 대응 규칙: 없다. MBTI는 "개발자가 정한다" (FAQ:L28).
6. "새로운 사람 우선"의 정량 정의(비율·감점·필수 여부)와 "다시 만나고 싶은 사람" 선호와의 관계가 없다 (PRD p.5 MAT-06, p.8 FDB-04).
7. 나이 계산 기준(출생연도 차이 vs 만 나이, 기준일): 없다. PRD는 "출생연도"를 입력받는다 (PRD p.4 ACC-02).
8. 성능 목표(100명 등)·실행 시간 제한: **1차 출처에 없다.**
9. 환불 경계(진행 2일 전 vs 화요일 24:00)·당일 취소·노쇼 제재·멤버십 연장 단위: 원칙만 있고 세부는 개발자 재량 (PRD p.1, FAQ:L21~25).
10. 신고 관계 제외 시점("신고 확정 관계" vs "신고 발생 즉시 분리"), 확정 후 3명이 된 테이블 처리 (PRD p.5 MAT-05, p.11 §15, FAQ:L26).

## 2. 매칭 상세

### 2.1 필수조건 (Hard)

| 조건 | 1차 출처 문구 | 상태 |
|---|---|---|
| 결제 완료·유효 신청 | "결제 완료" (PRD p.5 §7.0 표), "결제가 완료되고 신청이 유효한 사용자만 매칭 후보로" (PRD p.6 §7.1-2), "결제 미완료: 매칭 후보에서 제외" (PRD p.11 §15). CTO "✓ 결제 완료" (CTO p.8) | 확정 |
| 날짜·지역 | "날짜·지역이 맞는 참가자만 같은 후보군에 포함" (PRD p.5 MAT-02), "참가 가능 날짜·희망 지역 일치" (PRD p.5 §7.0), "참가자의 희망 지역 반영" (PRD p.1) | 확정 |
| 인원 4~6명 | "한 테이블을 4~6명으로 구성" (PRD p.5 MAT-02), "4명 미만 테이블은 절대 확정하지 않는다" (PRD p.6 §7.3) | 확정 |
| 연령 차이 | "연장자와 막내의 나이 차이가 8살을 넘지 않게" (PRD p.5 MAT-03), "나이 차이 8살 이내" (PRD p.5 §7.0, CTO p.8). 8살은 허용, 9살부터 위반으로 읽힌다 | 수치 확정. **나이 계산 기준은 미정** |
| 제외 관계 | "차단·신고 확정 관계와 다시 만나고 싶지 않다고 선택한 관계는 같은 테이블에서 제외" (PRD p.5 MAT-05), §7.0 "차단·신고·비선호 관계 없음" (PRD p.5) | 확정. 단, CTO p.8은 "차단·신고 관계 없음"만 쓰고 비선호를 빼먹었다(PRD 우선) |
| 신고 즉시 분리 | "피신고자와 신고자를 향후 매칭에서 즉시 분리" (PRD p.11 §15) | MAT-05의 "신고 확정 관계"와 시점 충돌 → 미정 |
| 중복 배치 금지 | "같은 사용자를 동시에 두 테이블에 배치하지 않으며" (PRD p.7 §7.4) | 확정(사용자 단위) |
| 결제 중복·실행 멱등 | "같은 참가자의 결제가 일정 이동 과정에서 중복 승인되지 않게", "동일한 매칭 작업이 여러 번 실행돼도 중복 테이블·중복 환불·중복 단체방이 생성되지 않아야" (PRD p.6 §7.3) | 확정 |
| 확정 전 재검증 | "확정 전 테이블 인원, 날짜·지역, 연령, 제외 관계 등 필수 조건을 시스템이 다시 검증" (PRD p.5 MAT-07, p.6 §7.1-9) | 확정 |
| 완화 금지 | "연령·차단·신고 등 필수 조건을 완화해 억지로 테이블을 만들지 않는다" (PRD p.6 §7.3), "자동 재배치 과정에서는 연령·차단·신고와 같은 필수 조건을 완화하지 않는다" (PRD p.7 §7.4), "필수조건은 완화하지 않는다" (FAQ:L26). K의 Q&A도 완화를 허용하지 않았다 (K:L64) | 확정 |

### 2.2 선호조건 (Soft)과 우선순위

| 항목 | 1차 출처 | 확정/미정 |
|---|---|---|
| 순서 — PRD Part 1 | "1순위: 연장자와 막내의 나이 차이 최대 8살 · 2순위: 성비 · 3순위: MBTI 궁합 · 4순위: 비슷한 관심사 · 5순위: 만나고 싶은 사람의 성향" (PRD p.1 "매칭 조건과 우선순위") | 순서 확정, 단 1순위가 필수조건과 겹침 |
| 순서 — PRD 기능표 | "연령대 → 성비 → MBTI 궁합 → 관심사 → 만나고 싶은 사람 순으로 조합 품질을 평가" (PRD p.5 MAT-04, P0) | 확정(PRD 우선) |
| 순서 — CTO | Soft score: "성비 우선순위 1 · MBTI 궁합 2 · 공통 관심사 3 · 희망 상대 성향 4 · 새로운 사람 비율 — 반복 만남 최소화" (CTO p.8) | PRD와 다름(§4 참고) |
| 선호조건 목록 | "성비, MBTI 궁합, 공통 관심사, 만나고 싶은 사람의 성향, 새로운 사람 비율" (PRD p.6 §7.0). **§7.0 선호 목록에는 "연령대"가 없다** | 목록 확정, 연령대의 soft 여부 모호 |
| 성비 | 선호조건. "단일 성별·한 명만 다른 성별 구성의 허용 및 점수 반영은 개발자가 정한다" (FAQ:L27) | 목표 비율·점수 미정 |
| MBTI | "공식 궁합 기준표는 없다. 궁합 기준은 개발자가 정한다" (FAQ:L28). MBTI는 복수 선택 입력 (PRD p.4 ACC-03) | 기준 미정 |
| 관심사 | "비슷한 관심사" (PRD p.1), "공통 관심사" (PRD p.6 §7.0). 관심사 분류 목록·유사도 계산식은 없음 | 계산식 미정 |
| 만나고 싶은 사람의 성향 | "본인 성향, 만나고 싶은 사람의 성향을 복수 선택" (PRD p.4 ACC-03), 결과에 "참가자별 만나고 싶은 사람의 조건 충족 여부" 표시 (PRD p.6 §7.2) | 충족 판정 규칙 미정 |
| 새로운 사람 우선 | "기본적으로 이전에 만난 사람보다 새로운 사람 매칭을 우선한다" (PRD p.5 MAT-06, P0), §7.0은 "새로운 사람 비율"을 선호조건으로 둠, §7.1-6 "이전 만남 이력을 평가", CTO "반복 만남 최소화" (CTO p.8), "새로운 사람 우선" (CTO p.12) | **원칙 확정(선호조건, 필수 아님). 정의 미정**: "이전에 만난 사람"의 범위(같은 테이블 동석 여부·기간), 비율 계산, MAT-04 순서 안 위치가 없다 |
| 피드백 반영 | "많이 참여한 사람일수록 매칭 알고리즘이 정교해져야" (PRD p.1 문제 4), "다음 매칭에서 이전 만남과 피드백이 반영된 것을 확인" (PRD p.12 §18-11) | 방법 미정. 자동 가중치 학습은 P2 (PRD p.5 MAT-16) |

해석: "새로운 사람 우선"은 PRD §7.0에서 선호조건으로 분류되므로 이전 동석자를 같은 테이블에 앉히는 것을 금지하는 필수조건은 아니다. "다시 만나고 싶지 않은 관계"만 필수 제외다.

### 2.3 점수·최소 점수·목적함수

| 질문 | 1차 출처 | 판정 |
|---|---|---|
| 점수 방식 | "조건별 점수를 합산해 가장 좋은 조합 선택" (PRD p.6 §7.0) | **가중 합산 구조는 확정**, 항목별 점수식은 미정 |
| 가중치 | "최소 매칭 점수와 선호 조건별 가중치는 운영자가 회차별 또는 서비스 전체 설정으로 관리" (PRD p.6 §7.0). 설정 UI는 "MAT-15 P1 가중치 설정" (PRD p.5) | 수치 없음. P0 본문과 P1 기능표 사이 경계 모호 |
| 최소 점수 | 자동 확정 기준 = "필수 조건 전체 충족 + 운영자가 설정한 최소 매칭 점수 이상" (PRD p.6 §7.0). "최소 점수보다 낮으면 다른 테이블 재배치 또는 대체 일정 안내로 전환" (같은 쪽). "사전에 정한 최소 점수를 충족하면 자동 확정할 수 있다" (PRD p.6 §7.3). CTO "4명 미만 또는 최소 점수 미달 → 자동 분리·병합·재배치" (CTO p.8) | **개념 확정, 값 미정.** 반면 MAT-10은 "모든 필수 조건을 충족하고 인원이 4~6명인 테이블은 … 자동 확정"으로 최소 점수를 언급하지 않는다 (PRD p.5) |
| 목적함수 범위 | "전체 조합을 최적화한다" (PRD p.6 §7.1-6), "필수 조건을 통과한 조합 중 가장 좋은 테이블을 선택" (CTO p.8) | 테이블 단위 최선인지 회차 전체 합 최선인지 모호 |
| 인원 최대화 vs 품질 | 명시 없음. PRD 목표·지표는 "매칭 성공률", "자동 재배치 성공률"을 측정하고(PRD p.3 §3) 동시에 최소 점수 미달 조합을 확정하지 말라고 한다(PRD p.6 §7.0) | **미정.** 해석: 두 요구를 함께 만족하려면 "최소 점수 이상인 테이블만 확정"을 제약으로 두고 그 안에서 인원·점수를 조정하는 구조가 PRD 문구에 가깝다 |
| 동점 처리 | 없음 | 미정 |
| 설명 우선 | "매칭 결과는 점수보다 설명 가능성이 먼저" (CTO p.9). 결과에 "추천 점수 또는 조건별 평가 결과" 표시 (PRD p.6 §7.2), 참가자에게 "다른 참가자의 개인정보나 상세 점수는 노출하지 않는다" (PRD p.5 MAT-12) | 확정(운영자에게 점수/평가, 참가자에게 이유만) |

### 2.5 관심사 유사도·성능·심사

- **관심사 유사도 계산식은 1차 출처에 없다.** "Jaccard", "유사도", "교집합"에 해당하는 표현은 PRD·슬라이드·CTO·K·FAQ 어디에도 없다. 쓰인 말은 "비슷한 관심사" (PRD p.1), "공통 관심사" (PRD p.6 §7.0, §7.2, CTO p.8)뿐이다. 매칭 결과 화면에는 "공통 관심사"를 표시해야 한다 (PRD p.6 §7.2). 대화 주제도 "공통 관심사와 대화 성향을 활용"해 최소 3개 만들어야 한다 (PRD p.7 CON-02).
- **성능 목표·시간 제한은 1차 출처에 없다.** 100명이라는 수치는 PRD·슬라이드·CTO·K·FAQ 어디에도 없다. 성능과 관련된 1차 문구는 "신청자 증가에 따라 조합의 경우의 수와 누락 가능성이 빠르게 증가" (PRD p.2 §2)뿐이다. 규모 참고값으로는 6~8월 총 신청 243건·실참가 142명 (PRD p.1), 06~09 총 신청자 300명·실참가 165명 (CTO p.5)이 있다(집계 기간이 다르므로 합치지 않는다). 사용성 목표로 "최초 신청은 … 5분 안에 완료" (PRD p.11 §16)가 있다.
- **심사 포인트(매칭):** "자동 매칭 — 참가자 조건을 반영한 테이블 자동 매칭 구현 정도 25점" (슬라이드 p.7). 연관: "피드백 반영 — 피드백 수집과 다음 매칭 반영의 완성도 15점" (슬라이드 p.7). 평가 세부 기준표는 없다. PRD 완료 조건 3~5·11단계가 매칭 시연 기준이다: "필수 조건과 우선순위에 따라 4~6인 테이블을 생성", "4명 미만 또는 조건 미충족 조합을 해제하고 … 자동 재배치", "운영자 승인 없이 자동 확정", "다음 매칭에서 이전 만남과 피드백이 반영" (PRD p.12 §18). CTO는 "매칭 결과는 점수보다 설명 가능성이 먼저" (CTO p.9), 목표 지표 "자동 확정률 ↑ 운영자 개입률 ↓" (CTO p.7)를 강조한다.
- **매칭 결과 필수 표시 12항목:** 인원수, 참가자별 희망 날짜·지역 충족, 최고·최저 연령과 차이, 성비, MBTI 구성, 공통 관심사, 만나고 싶은 사람 조건 충족, 이전 만남 여부, 차단·비선호 충돌, 추천 점수 또는 조건별 평가, 재배치 횟수·최종 사유, 확정/실패 시각 (PRD p.6 §7.2).
- **기록:** "자동 매칭 버전, 적용 기준, 생성·분리·병합·재배치·확정 결과를 기록" (PRD p.11 §16). MatchRun에 "알고리즘 버전", DiningTable에 "조건별 점수" (PRD p.10 §13).

구분: **[내부결정]** = 사용자·팀 승인으로 생긴 결정(1차 출처에 없음), **[불일치]** = 1차 출처와 다르게 적음, **[근거누락]** = 1차 출처에 없는데 출처가 있는 것처럼 적음.

## 6. 즉시 결정이 필요한 질문 (다음 작업: 매칭 관심사 점수 구현 기준)

1. **인원 최대화 vs 품질의 최종 관계.** PRD §7.0은 "최소 점수 미달 → 재배치/대체 일정"이다. 인원을 1순위로 두고 점수를 2순위 동점 처리로만 쓰는 현재 방식(D1·D2)을 최종으로 할 것인가, 최소 점수를 제약으로 넣을 것인가? (PRD p.6 §7.0, §7.3)
2. **"연령대" 선호 점수의 실체.** 8살 상한(필수) 외에 "나이가 가까울수록 가점"을 MAT-04 1순위로 둘 것인가? 아니면 CTO p.8처럼 성비부터 시작할 것인가? (PRD p.5 MAT-04 vs CTO p.8)
3. **우선순위의 구현 형태.** "연령대 → 성비 → MBTI → 관심사 → 성향"을 사전식(lexicographic) 비교로 할 것인가, PRD §7.0 문구("조건별 점수를 합산")대로 가중 합산(가중치 내림차순)으로 할 것인가?
4. **관심사 점수식.** Jaccard를 유지한다면 "모든 쌍의 합"이 6인 테이블을 구조적으로 우대하는 문제를 받아들일 것인가, 쌍 평균으로 바꿀 것인가? 또 결과 화면의 "공통 관심사"(PRD p.6 §7.2)를 테이블 전원 교집합으로 볼지 2인 이상 공유로 볼지?
5. **최소 매칭 점수 기본값과 설정 위치.** 값이 없다면 0(사실상 미적용)으로 두고 운영자 설정만 만들 것인가? (PRD p.6 §7.0, MAT-15 P1, U14)
6. **새로운 사람 우선의 정의.** "이전에 만난 사람" = 과거 같은 테이블 확정·참석자로 볼 것인가? 감점 방식과 MAT-04 순서 안 위치는? 재만남 희망(FDB-04)과 충돌할 때 어느 쪽이 우선인가? (PRD p.5 MAT-06, §7.0)
7. **나이 계산 기준.** 출생연도 차이 ≤ 8을 공식 해석으로 확정할 것인가? (D7)
8. **상태 정정.** 배정 실패자를 PRD대로 ALTERNATIVE_OFFERED로 전환하고 NO_MATCH는 대체 일정도 없는 종료로만 쓰는 정정 시점 (D6)
9. **사용자 단위 중복 배치 금지**를 언제 반영할 것인가 (PRD p.7 §7.4, D5)
10. **신고 관계 제외 시점:** 접수 즉시(§15)인가 확정 후(MAT-05)인가?
