# 합성100명 신청·모의 결제 시연 시나리오

위치: **자동 매칭·실패 해결 → 규칙·데이터·정답 기준 → 가상데이터 변환·DB 시드 구축** (Work #5). 2026-10-17 사용자 B안 승인: 기존 심사용 계정은 처음부터 체험 가능하게 유지하고, 별도 합성100명으로 동의·신청·모의 결제를 준비한다. 새 Work/Task를 만들지 않고 [PR #36](https://github.com/InryeolChoi/SerenTable/pull/36) 계정 시드의 후속 PR로 분리한다.

## 실행 경계

- `python -m serentable.seed_demo_scenario --slot-id UUID [--target local|railway]`를 명시 실행한다. 운영자가 기존 어드민 화면/API로 만든 **정원100의 전용 회차 ID**를 입력한다. 회차를 자동 생성·이동·재예약하거나 마감을 바꾸지 않는다.
- [합성 시드 계약](./synthetic-demo-seed-contract.md)의 대상·실행별 opt-in·암호 검사를 재사용한다. local은 loopback 앱 HTTP만, railway는 고정 프로젝트/환경/API 서비스와 `https://chanceplate.up.railway.app`만 사용한다. 주소에 자격 증명·경로·query·fragment를 허용하지 않고 HTTP redirect를 따라가지 않는다.
- DB에 업무 레코드를 직접 INSERT하지 않는다. 실제 앱의 CSRF·로그인·목적별 동의·신청·모의 결제 API를 순서대로 호출한다. HTTP 클라이언트는 표준 라이브러리이며 새 런타임 의존성은 없다.
- 계정은 `synthetic-demo-001`~`100`과 결정적 ID가 모두 일치하고 프로필이 완성되어야 한다. 기본 참가자4명·운영자 프로필/동의/신청은 변경하지 않는다. 전용 회차에 이외의 참가자가 한 명이라도 있으면 쓰기 전에 거부한다.

## 합성 동의·거래와 재실행

- 현재 정책의 목적·버전·합성 데모 표기와 상품의 mock 여부를 확인한다. 이 기록은 실제 개인정보 동의나 실제 매출/참석이 아니라 **합성 계정에 대한 시연 fixture**다. 원본294응답과 연결하지 않는다.
- 100명의 기존 동의를 먼저 점검한다. 기록이 전혀 없으면 합성 동의를 생성하고, 이미 완성된 동의는 보존한다. 거절·철회 기록이 있으면 어느 참가자의 동의/신청/결제도 새로 쓰기 전에 중단한다.
- 신청 키와 모의 결제 키는 회차·합성 계정 ID에서 UUIDv5로 결정한다. 재실행은 같은 신청/같은 결제를 반환받는다. 취소된 신청을 되살리거나 다른 결제/이용권을 가져오지 않는다.
- 전체100명은 **하나의 DB 트랜잭션이 아니다.** 각 API 호출만 원자적이며, 네트워크·DB 오류 시 이미 준비된 사람은 남는다. 같은 회차 ID로 재실행하여 중복 없이 이어간다. 실패 출력은 정적 오류 코드와 완료 인원만 포함한다. 원시 응답·URL·비밀번호를 출력하지 않는다.
- 마감 전에 준비가 끝나야 한다. 마감 후에는100명 전원이 이미 SUBMITTED·모의 결제 완료일 때만 멱등 재실행을 허용한다. 부분 준비 상태에서 마감됐으면 중단하며 시간을 되돌리거나 미결제를 강제로 통과시키지 않는다.
- 매칭은 기존 별도 worker가 회차의 실제 `matches_at`에 자동 실행한다. CLI에는 강제 매칭·수동 확정·시간 제어 기능이 없다. 생성한 세션은 정리하고, 정리 실패 시 기존 세션 만료/철회 정책을 따른다.

## 검증

주 경계는 외부 CLI → 실제 HTTP 서버 → 실제 PostgreSQL과 별도 worker다. 모듈 부재 RED 확인 후 구현했다. 원본·준비 DB·운영 DB에는 쓰지 않았다.

- 로컬 합성100명으로 동의·신청·모의 결제100건 준비, 재실행 후 신청/거래 ID·시각 유지.
- 실제 마감 후 별도 worker100명 확정, 독립 필수조건 검사 위반0. 종료 후 시나리오 재실행도 배치/거래를 늘리지 않음. 집중 시험1 PASS(100.40초, 실제90초 마감 대기 포함).
- 일반 참가자가 섞인 회차 및 기존 동의 거절을 사전 거부하고 기존 데이터/아직 미작성인 동의를 보존하는2개 시험 PASS(10.41초).
- 중간 실제 DB 오류의 부분 준비·재시도 검증, 최종 CI·독립 검토는 후속 기록에서 확정한다.

## 배포·상태
