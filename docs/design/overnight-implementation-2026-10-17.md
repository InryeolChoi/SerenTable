## 작업 범위

사용자 요청은 취침 중 진행 가능한 구현이다. 기존 Agenda → Work → Task와 승인된 정책 안에서 진행하며, 새 Work/Task는 만들지 않는다. 사용자 수정 중인 AGENTS.md·도구 설정·개인 실행 스크립트는 보존한다. 구현은 메인 에이전트가 맡고 복잡한 상태·동시성·권한은 읽기 전용 specialist로 검토한다.

|---|---|---|
| 자동 매칭·실패 해결 → 규칙·데이터·정답 기준 → 100명 실행 사례와 작은 정답 사례 준비 (#5) | 원본과 무관한 테스트 전용 합성 100명, 실제 PostgreSQL·별도 worker 실행과 독립 필수조건 검사 | API로 신청·결제·결과를 확인하고 100명 결과·실측 시간을 기록. SLA 확정과 원본 DB 시드는 별개 |

### 첫 구현 검증

- API RED: 확정 뒤 1회권이 `HELD`로 남아 `USED` 기대와 불일치. 배치 이력으로 사용 상태/시각을 산출한 뒤 같은 시험 GREEN.
- 대체 일정 API RED: 경로 없음(404). 구현 뒤 PostgreSQL HTTP 3개 시험 PASS(본인 조회·대기 후보·권한/소유권).
- 모바일 Chromium: 확정된 1회권의 사용 완료·미매칭 이유·다른 모집 일정 안내 PASS. 최신 정적 번들을 빌드한 결과이며 실제 휴대폰/운영 배포 시험은 아니다. 중간 실행 2회는 이전 번들을 사용해 실패했으므로 결과에 포함하지 않는다.
- 원본 무관 합성 100명: 실제 HTTP로 프로필·동의·신청·모의 결제 후 별도 worker가 100명을 18개 테이블로 확정했다. 1990년생 50명·2005년생 50명으로 두 그룹마다 5명씩 10테이블이라는 독립 증거가 존재하므로 최대 100명이 정답이다. 결과 테이블을 운영자 API로 읽어 독립 필수조건 검사 위반 0을 확인했다. 로컬 PostgreSQL17, Python3.12의 프로세스 시작+DB 작업 0.566초이며 준비/신청/실제 마감 대기까지 시험 52.41초다. 한 사례의 실측이며 U19 SLA 확정·브라우저 100동시 접속·운영 부하는 아니다.
- 실제 PostgreSQL17 전체 API/오라클 회귀 **129 passed**(194.55초). 확정 마지막 DB 저장 오류 주입→전부 롤백(참가자 EXCEPTION·테이블 없음·1회권 HELD)→다음 세대 재시도(CONFIRMED·USED), NO_MATCH의 HELD 유지, 멤버십 ACTIVE 유지가 포함된다. Python3.12·잠금 의존성, `PYTHONPATH=backend`와 동일한 테스트용 DATABASE_URL/TEST_DATABASE_URL로 `uv run pytest -q`를 실행했다.
- 고정 `39dd3d0...505da29` 독립 검토: Standards는 차감 시점 표의 오래된 문구 1건(P3)을 지적해 정정, Spec은 결함·범위 이탈 0건. 두 검토는 읽기 분석이며 제품 시험 재실행이 아니다. 후속 배치 종료/이미 지난 잔여 후보의 전용 회귀·자원 사용량 측정은 검토상 비차단 보완점이며 미실행으로 남긴다.
- Ruff check·format PASS, Node22 TypeScript/Vite build PASS. 전체 Chromium 브라우저 **10 passed**(34.3초), 매칭 시험의 별도 참가자/운영자 세션에 Pixel7 설정을 명시했다. 참가자 가로 잘림 없음과 [대체 일정 화면 캡처](./evidence/matching-alternatives-mobile.png)를 확인했다. 실제 휴대폰·운영 배포 시험이 아니다. 최종 CI(이미지·PG18 격리 복원 포함)는 [PR #33 checks](https://github.com/InryeolChoi/SerenTable/pull/33/checks)에서 확인한다.

## Blaybus 수동 반영 문구

공통 PR: https://github.com/InryeolChoi/SerenTable/pull/33 (병합 완료). 새 Work/Task 추가는 없다. 실제 투입 시간은 사용자 타이머 기록을 사용한다. **100명 실행 사례와 작은 정답 사례 준비 Task는 사례 준비 범위에서 완료로 표시할 수 있다.** 성능 SLA·데모 시드는 별도다. 나머지 두 Task와 Work #5/#6·Agenda는 진행 중을 유지한다. Blaybus 실제 변경은 사용자 수동이며 반영 확인 전이다.

