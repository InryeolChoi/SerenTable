# Work9 예외 연결·모의 환불 복구 검증

2026-10-19 KST. 기존 Agenda → 운영자 예외·안전 종합 관리(#9) → 기능별 예외·조치 연결 / 권한·처리 이력 검증. 추가 Work·Task 없이 [PR44](https://github.com/InryeolChoi/SerenTable/pull/44)에 모은다. 기준66eaeb6(PR42·43이 병합된 Work7 통합) → 통합 codex/w9-resolution-integration. 운영 반영 없음.

## 수행

- 푸시 3회 실패 예외의 회차 식별 누락을 수정했다. 식당 테이블이 없는 푸시 예외도 delivery→notification→table 연결로 해당 회차를 표시한다. 일반 알림은 회차를 임의로 만들지 않는다.
- [ADR0015](../adr/0015-operator-failure-recovery.md)의 사용자 승인에 따라 대안 미응답을 원래 실패 회차 시작 이후의 운영자 표시로 확정했다. 참가자 이동·보관·환불 선택을 만료시키지 않는다.
- 0014 추가 시도 이력으로 DB 기반 모의 환불 실패·운영자 재시도를 구현했다. 금융 savepoint 실패 시 PAID·활성 권리 예약은 보존하고 신청 후보는 종료한다. 성공 시 기존 3개 환불 이벤트·REFUNDED·예약 종료를 함께 반영한다.
- 실패 기록·감사·최종 커밋 장애는 전체 롤백한다. 실패 기록을 쓸 수 없는 DB 장애에 기록 보장을 주장하지 않는다. 원금·사용자·결제는 서버가 원본에서 결정한다.
- 참가자 화면에서 저장 실패를 환불 완료로 오표시하던 문제를 브라우저에서 재현하고 수정했다. 운영자 예외 목록에 실패·금액·재시도 버튼을 연결하고 대시보드에 실패 환불과 대안 미응답 수를 포함했다.

## 검증 경계와 실행 기록

승인된 실제 PostgreSQL HTTP/API·별도 Worker·브라우저 경계다. 저장 장애는 격리 DB trigger, 푸시 공급자 실패는 외부 전송 경계의 가짜 응답으로 주입한다. 구현 내부 함수를 가짜로 바꿔 성공을 만들지 않는다.

- 푸시 회차 연결: RED1 FAIL→GREEN1 PASS(6.20초), 기존 예외·대시보드 포함11 PASS(49.60초).
- 환불 최초 저장 장애: 기존503 RED→FAILED와 예약 보존 GREEN. 신규8 PASS(22.68초). 기존 실패 해결17+당시 신규5의 순차 검증22 PASS(72.94초).
- 신규8개는 동일키 중복·동시 요청, 다른 해결 선택 거절, 재사용 방지, 역할·CSRF·금액 입력 거절, 감사 실패 롤백, 실패 이력 기록 불가, DB 지연 제약의 최종 commit 실패, 0013 과거 성공 환불의 0014 upgrade 보존을 포함한다.
- 작업자 중간 시험에서 동일 전용 DB에 시험 프로세스를 겹쳐 실행한 준비 오류(6 FAIL·10 PASS)가 있어 중단하고 순차 재실행했다. 또 다른 중간 1 FAIL은 동일 날짜/지역 회차 중복 생성 fixture 오류였다. 위 순차 결과가 최종 증거이며 중간 실패를 제품 회귀로 감추거나 성공으로 계산하지 않는다.
- 목록 연결: RED1 FAIL/1 PASS(환불 예외가 목록에 없음) → GREEN2 PASS(5.31초). 대안 표시 후에도 참가자가 보관 선택할 수 있음·권리 재사용 가능 확인.
- 새 브라우저 시나리오: 기존 화면 RED1 FAIL(실제 FAILED인데 완료 표시) → 수정 후1 PASS(10.9초). 최종 오류 없이 회차별 정확한 카드에서 실패 표시→운영자 재시도→재조회 완료·환불 3개 이벤트를 확인했다.
- 전체 모바일 Chromium **12 PASS(58.4초)**. 기존 신청·결제·매칭·안내·평가·권한 흐름을 포함한다.
- 타입/빌드·Ruff·형식·diff 검사 통과. 전체 API·최종 CI 결과는 아래 최종 기록에서 확인한다.

DB는 foundation 테스트 컨테이너의 신규 serentable_w9_push_test, serentable_w9_refund_test, serentable_w9_resolution_test, serentable_w9_review_test와 serentable_test_w9_recovery_e2e만 사용했다. 루트 사용자 AGENTS/.claude/.codex/scripts 미커밋 파일·원본·보존 DB를 수정하지 않았다.
