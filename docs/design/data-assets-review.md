검토일: 2026-10-15. 대상 Task: `개발·배포 기반 확보 → 요구사항·설계·자료 정리 → 가상데이터 구조와 누락값 확인`. 원본 재감사이며 데이터 변환·시드 생성은 수행하지 않았다.

## 가상데이터

출처: 로컬 `data/우연한식탁_가상데이터.xlsx`의 `설문지 응답 시트1`.

- 1행은 비어 있고 2행이 헤더다. 값이 있는 행은 헤더 포함 295개이며 이름이 있는 응답 행은 294개다. 시트의 읽기 결과 395행을 참가자 수로 사용하지 않는다.
- 서로 다른 이름 문자열은 258개다. 동명이인/반복 신청/가명 반복을 구별할 식별자가 확인되지 않았으므로 이름만으로 사용자를 병합하지 않는다.
- 294개 행에 나이·성별·MBTI·지역·관심사·본인/희망 성향·가격대·날짜·이용권·동의가 있다. 연락처·Instagram ID·직업은 모든 응답에서 비어 있다.
- 못 먹는 음식은 124개 행에 값이 있다. 빈 값이 알레르기 없음 또는 안전 확인 완료를 의미한다고 가정하지 않는다.
- MBTI에 `Entj` 같은 대소문자, 복수 유형, 설명 문장, `WNTJ`·`LSTP` 등의 비표준 값이 있다. 임의 오타 보정이나 첫 유형 선택은 하지 않는다.
- 날짜는 연도 없는 월/일·요일 문자열이며 여러 날짜가 있는 응답도 있다. 데모 일정으로 옮기려면 원본과 별도의 변환 규칙이 필요하다.
- 관심사 등은 쉼표로 나뉜 문자열이지만 `운동 (헬스, 러닝, 클라이밍 등)`처럼 항목 안에도 쉼표가 있다. 단순 쉼표 분리는 오분류를 만든다.
- 출생연도가 아닌 나이가 있다. 기준 연도·연령 계산 방식을 확인하지 않고 PRD 출생연도로 역산하지 않는다.
- 결제 완료 상태·출석·피드백·이전 만남·차단 관계의 독립 데이터는 확인되지 않았다. 이용권 선택이나 개인정보 동의를 결제 완료로 간주하지 않는다.

따라서 입력 정규화와 데모용 보완 데이터를 별도 Task로 준비한다. 원본은 보존하고 생성 값/시나리오를 명시한다. 실행당 100명 목표는 전체 294행의 원본 축소나 고유 사용자 수 확정을 뜻하지 않는다. 정책은 아직 미결정이다.

이름은 앞뒤 공백만 제거한 문자열 기준 258종이다. 30개 이름 문자열이 두 번 이상 등장하며 해당 그룹에 속한 응답은 총 66행이다. 이 수치는 반복 신청자 수나 고유 인원수가 아니다. 가명 필드이며 연결 가능한 식별자·실제 연락처가 없으므로 동일 이름을 동일인으로 병합하거나 재회 이력을 생성하지 않는다.

원본은 신청 설문 구조다. 이용권 선택은 있지만 결제·환불 거래 식별자, 결제 완료 상태, 이용권 잔액·유효기간·사용 내역은 없다. 별도 출석·노쇼·후기 점수·이전 테이블·재회 회피·차단 관계·식당 목록도 제공되지 않았다. 다른 열이나 반복 이름에서 이 정보를 추정할 수 없다.

### 재현 및 비수정 검증

저장소 루트에서 Python 3 표준 라이브러리만으로 다음 명령을 실행한다. 경로는 실제 제공 원본을 인자로 전달한다.

```bash
python3 scripts/audit_source_data.py /absolute/path/to/source.xlsx
```

스크립트는 이 제공 파일의 2행 헤더·A:Q 배치에 맞춘 읽기 전용 감사 도구다. 다른 레이아웃에 그대로 적용하지 않는다. ZIP/XML을 읽고 집계만 출력하며 이름·연락처·개별 응답은 출력하지 않는다. 수식이나 셀 문자열을 실행하지 않으며 파일을 저장하거나 외부로 전송하지 않는다. 헤더·시트명도 입력 데이터로만 취급한다.

검증: 표준 라이브러리 집계를 반복 실행하여 같은 결과를 확인했고, 별도 `openpyxl` 읽기 전용 추출과 응답·누락·MBTI·날짜 집계를 대조했다. 원본 SHA-256을 읽기 전후 비교하여 불변임을 확인했다. 문서와 집계 도구만 변경하므로 제품 단위 테스트나 데이터 변환 테스트는 추가하지 않았다.

| 원본 | SHA-256 |
|---|---|
| 우연한식탁_가상데이터.xlsx | `8c6fc783e9dab9e047f5bc6fe0667e521cf44951808e56f49f3fe6eaf3e54a7a` |

이름의 Unicode 정규화·대소문자 변환·유사도 병합은 적용하지 않았다. 원본의 결측을 채우는 작업도 수행하지 않았다.

### 기존 후속 Task에서 다룰 사항

명세의 U17은 계속 미결정이다. 새 Task를 추가하지 않고 기존 `자동 매칭·실패 해결 → 규칙·데이터·정답 기준` Work의 다음 두 Task에서 처리한다. 이번 감사에서는 정책 확정·데이터 변환·시드 생성을 실행하지 않았다.

- 이유: 원본을 매칭·인증·결제 E2E의 유효한 입력으로 바로 사용할 수 없다.
- `입력 정규화·누락값·식별 정책 결정`: 이름 식별, 날짜·나이 기준, MBTI·관심사·가격 파싱, 누락값 보완, 원본과 생성 값의 구분 규칙을 승인받는 것을 완료 기준에 포함한다.
- `100명 실행 사례와 작은 정답 사례 준비`: 승인된 규칙에 따라 사례를 만들고 생성된 거래·이력을 표시하여 원본 자료와 데모 시드를 구별할 수 있는 것을 완료 기준에 포함한다.
- 일정 영향: 기존 Task 분할과 실행 순서를 유지한다. 규칙 승인 전에는 이 원본을 사용하는 매칭 입력·데모 시드 구현이 대기한다. 이미 완료한 배포와 운영 검증에는 영향이 없다.
