# 매칭 필수조건 독립 검증자 (Work #5, A3-W1)

향후 매칭 엔진의 결과를 비교할 **독립 검증자**다. 엔진 코드와 공유하지 않도록 `backend/serentable` 밖의 `tests/oracle/hard_constraints.py`에 순수 Python(DB·FastAPI 없음)으로 둔다. 엔진이 이 모듈을 import하지 않는 것을 원칙으로 한다. 시험은 `tests/oracle/`에 있으며 기대값은 손으로 계산한 값이다.

## 입력

- 참가자: `id`, 결제 완료 여부(`paid`), 동의한 후보 회차 키 집합(`consented_slots`, (날짜, 지역) 쌍 또는 회차 id 등 불투명 키), `birth_year`.
- 제외 관계: 불투명한 참가자 쌍 집합. 차단·신고·비선호 중 무엇을 제외로 볼지(U09)는 호출 측에서 정해 넘긴다.
- 제안 배치: 회차 키별 테이블(`Table(table_id, slot, members)`).

## 검사하는 필수조건 (완화 불가)

`validate_assignment()`는 bool이 아닌 `Violation(rule, table_id, participant_ids, related_table_ids)` 목록을 반환한다.

| Rule | 내용 |
|---|---|
| `UNKNOWN_PARTICIPANT` | 입력 참가자 목록에 없는 구성원 |
| `TABLE_SIZE` | 고유 구성원 수가 4~6명 밖 |
| `UNPAID` | 결제 미완료 구성원 |
| `NOT_CONSENTED` | 테이블 회차에 동의하지 않은 구성원 |
| `AGE_GAP` | 나이 키의 최대−최소 > 8 (양 끝 참가자 보고) |
| `EXCLUDED_PAIR` | 제외 쌍이 같은 테이블에 있음 (순서 무관) |
| `DOUBLE_BOOKED` | 한 참가자가 배치 전체에서 두 번 이상 등장 (같은 회차·다른 회차·같은 테이블 중복 모두) |

다른 회차 간 중복도 위반으로 본다. 명세의 “같은 신청의 살아 있는 배치 소유권은 하나”를 따르며, 입력 참가자 1명을 신청 1건으로 취급한다. 복수 회차 경합·소유권 이전(U07)은 다루지 않는다.

## 잠정 해석: 나이 차이

PRD의 “연령 차이 8살 이내”를 **출생연도 차이**로 계산한다. 이는 U02/U17(나이 기준·과거 데이터 변환) 확정 전의 잠정 해석이다. 만 나이·회차 기준일 나이 등으로 바뀔 수 있으므로 `age_key` 인자로 교체할 수 있다. 상한 8 자체는 PRD 확정값이다.

## 작은 사례 기준: `max_seatable()`

12명 이하 입력에서 필수조건만으로 **동시에 앉힐 수 있는 최대 인원**을 전수 탐색으로 구한다. 후보 테이블은 `validate_assignment()`로 판정하므로 검증자와 같은 필수조건 정의를 쓴다. 결과의 `tables`는 최대 인원을 달성하는 임의의 한 배치(증거)이며, 비교 대상은 `seated_count`뿐이다. 이 값은 **품질·점수 최적해가 아니다**. 참가자 수 최대화와 점수 우선순위는 U06에서 정한다. 12명을 넘으면 `ValueError`를 낸다.

예: 자격자 7명은 4~6의 합으로 만들 수 없어 최대 6명만 앉는다. 출생연도 1990·1994·1998·2002 각 2명은 6+2가 아닌 4+4로만 8명이 앉는다.

## 의도적으로 검사하지 않는 것

- 점수·가중치·최소 점수·목적함수·탐색 알고리즘(U05, U06, U14)
- 복수 회차 경합·확정 타이밍(U07), 재배치 순서 준수
- 제외 관계의 출처와 시점(U09): 쌍 집합만 입력으로 받는다
- 입력 정규화·원본 데이터 변환(U17), 100명 성능 기준(U19)
- 신청 상태·마감 시각·결제 상태 전이 등 DB 상태. `paid`는 호출 측이 판정한 값이다.

이 검증자의 통과는 엔진의 필수조건 준수만 뜻하며, 제품 시험 통과나 매칭 품질을 뜻하지 않는다.
